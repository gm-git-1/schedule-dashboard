How to build an agent that builds the culture — Zach Bruggeman, Ramp

AI Engineer · Zach Bruggeman, engineer at Ramp · uploaded 21 Nov, 1:30 AM IST · 14:28
Verdict: skim from 7:02 — the telemetry-bug story and Review Buddy are the fresh parts; the rest is culture talk about agent adoption, which is well-covered ground.
🔁 Repeat: 'coding agents in production' — seen 92 times before. New here: Ramp's number (about 75% of its code is now written and shipped by its in-house agent Inspect) and the culture side of getting there, rather than the plumbing.
🔁 Repeat: 'AI fluency / enablement' — seen 13 times before. New here: no training sessions and no mandate; every agent session is public inside the company by default, so people learn by watching teammates.
🔁 Repeat: 'AI-generated code validation' — seen 42 times before. New here: little beyond reviewers seeing the full agent conversation, screenshots and a verification-agent video next to each PR.
What Inspect is
  • Ramp's own multiplayer agent: Inspect runs every session remotely in a sandbox (spun up in under 5 seconds), works from Slack, Linear and other tools, and is wired into company data like telemetry and databases. About 75% of Ramp's code is now written and shipped through it, and it is now sold outside Ramp (0:12–1:34)
  • Why one shared setup: 15 minutes of personal agent setup multiplied across hundreds or thousands of people is days lost, and it repeats every time best practices change. One company-wide Inspect means an improvement anyone makes reaches everyone, and they never had to mandate its use (2:14–4:18)
Learning and trust in public
  • Sessions are public by default: Because working in public is easier than private, people learn by watching teammates. You can even ask Inspect to look through a colleague's recent sessions and explain how they write prompts. The Inspect team also uses this to decide what to build next (4:18–5:40)
  • PRs come with proof: Reviewers see not just a 400-line diff but the conversation, the tools used, before/after screenshots, or a video of the verification agent clicking through the app (6:20–7:02) (repeat)
  • Telemetry bug story: A user reported a bug and Inspect blamed its own newly added tracing, which nobody believed (the user said he'd just use Claude Code). Prodding in the open thread found the real cause: the OpenTelemetry exporter for Cloudflare Workers called fetch without reading or cancelling the response body. Inspect patched it, errors stopped, and within an hour the sceptic became a collaborator (7:02–9:43)
Thinking bigger together
  • Against the lone-wolf operator: He argues that AI making individuals more productive can't be the endgame. Without sharing and collaborating, teams only build for themselves (10:09–11:04)
  • Review Buddy: Two engineers, tired of rotating between off-the-shelf code review products, built Ramp's review agent on Inspect's existing PR-opened triggers without asking permission. That pushed the Inspect team to see it as more than a coding agent (11:39–13:07)
  • Ask your team: His closing advice is to ask colleagues "what have we been waiting to do?" and build it together. Waitlist at inspect.com/aie (13:07–14:28)

Engineer Your Coding Agents Like Any Other System — Zach Lloyd, Warp

AI Engineer · Zach Lloyd, founder & CEO, Warp · uploaded 21 Nov, 12:00 AM IST · 18:31
Verdict: skip — a third telling of Warp's software-factory pitch; only the redundant-tests eval example is new.
🔁 Repeat: 'software factory' — seen 26 times before. This is Zach Lloyd's third version of this talk in the history (after 27 Sep and 9 Nov). New here: very little.
🔁 Repeat: 'self-improving agents' — seen 27 times before. New here: nothing beyond agents proposing PRs against the factory definition.
🔁 Repeat: 'evals for agents' — seen 71 times before. New here: one concrete online eval that flags coding agents writing redundant tests.
Why local agents don't scale
  • Where most teams are: Developers still run coding agents locally and prompt them one at a time. That caps throughput at human speed and makes cost, productivity, security and governance hard to control when everyone picks their own models and skills (1:22–2:42) (repeat)
  • His definition: A software factory is "a code-defined, closed-loop system for continuously measuring and improving cloud coding agents". It is not a loose set of automations, AI teammates, shared skills/MCPs, or personal agent swarms (2:42–5:26) (repeat)
The factory stack
  • Layers: From the bottom: factories as code (Terraform-style, so you can branch, roll back and self-improve), recording every agent run and its artifacts, multi-platform sandboxes, swappable models and harnesses (Claude Code, Codex, Pi, Warp or your own), orchestration, and an API/MCP-first surface plugged into Slack, Linear, Jira and GitHub (8:07–10:50) (repeat)
  • Demo, live view and metrics: A Google Docs–style live view of every agent on Warp's team (for example a colleague implementing Opus 5.5 from Slack), plus DORA-style cycle time, human interactions per PR, throughput and cost (11:30–13:32)
Measure and improve
  • Online evals: An agent re-scores recorded sessions. Warp's example eval catches agents writing unnecessary tests so the cause can be fixed in the factory (13:32–14:55)
  • Self-improvement and benchmarks: Agents look for patterns in failed runs and open PRs against the factory config. Real tasks are replayed against different models, harnesses or skill sets to get a cost-vs-quality chart on your own data instead of SWE-bench (14:55–17:38) (repeat)

Rust Desktop Framework Generates UI Without A Browser (GPUI)

Better Stack · Warren, Better Stack · uploaded 20 Nov, 4:37 PM IST · 6:50
Verdict: worth watching (under 7 min) if you ship desktop apps — fresh topic with concrete benchmark numbers.
Why Discord is dropping Electron
  • The switch: Discord is rebuilding its desktop app in Rust using GPUI, the UI framework from the team behind the Zed editor (Zed's founder helped create Electron). Discord says clicking around "feels instant" and it boots much faster (0:00–0:41)
  • GPUI vs Electron vs Tauri: Electron ships its own copy of Chrome. Tauri (which Epic just moved its game launcher to) uses the browser engine built into the OS. GPUI drops HTML/CSS entirely and draws with Metal on Mac and Direct3D on Windows. On phones, the same Rust code drives native controls (0:41–2:01)
How it draws like a game
  • Shaders in batches: Each primitive type (rectangles, shadows, text, images) has its own small GPU shader. Everything on screen is sorted into piles by type and each pile is sent to the GPU in one go. Rounded corners and shadows are pure maths, so there's no blur step (2:01–3:21)
  • Text and code: Letters are drawn once into a "glyph atlas" in GPU memory and then copied onto the screen. The code uses Tailwind/SwiftUI-like chained styles with flexbox layout. The screen is rebuilt every frame, with an option to reuse unchanged parts (3:21–4:43)
Benchmarks on the same chat app (Mac)
  • Memory and size: Idle memory was 88 MB for GPUI, 142 MB for Tauri and 150 MB for Electron. App size was 4.66 MB, 6.7 MB and 259 MB (4:43–5:24)
  • Under load: Scrolling 500 messages, posting every 0.1 s and switching channels: GPUI held 60 fps at about 120 MB and Tauri held 60 fps at 200+ MB. Electron hit about 320 MB and dropped to about 50 fps. But GPUI used almost twice Tauri's CPU while scrolling (4:43–6:04)
  • His take: Thin docs, frequent breaking changes and Rust complexity buy very little performance gain, sometimes none, so Electron or Tauri remain the lower-risk choice for most apps (5:24–6:50)

The Hidden Claude Code Setting That Shows What Claude Really Changed

Better Stack · Andress, Better Stack · uploaded 20 Nov, 8:36 AM IST · 9:21
Verdict: worth watching — new Claude Code feature with careful measurements and a real safety caveat.
🔁 Repeat: 'Claude Code' — seen 4 times before. New here: the experimental Code Mode flag itself, tested with real numbers.

Note: the auto-captions say "about 80% faster", but the video description says about 18%. 18% is used below.

What Code Mode is
  • One program instead of many tool calls: With Code Mode on, Claude writes a short JavaScript program that calls Claude Code's own read/edit/shell tools, can run them in parallel, and sends only the final result back to the model. Variables stay in memory between programs. To see the code it wrote, press Ctrl+O, then Ctrl+E (0:00–2:02)
  • How to turn it on: It needs Claude Code 2.1.323+ (native build) with the experimental Code Mode environment variable set. It only works in the interactive terminal with a subscription or Console account: not with -p, the Agent SDK, VS Code or Bedrock, and not if you export OpenTelemetry (2:02–2:42)
The refactor test
  • Setup: A TypeScript Express "fake store" API with 53 files and 166 console calls to migrate to a structured Pino logger shipping to Better Stack, with planted traps. He ran it 3× off and 3× on with Opus 5.5 at medium effort in auto mode (2:42–4:05)
  • Results: Quality was identical (0 console calls left, all 56 tests passing, traps untouched). Code Mode was about 18% faster, needed about 28% fewer model round trips, and its three runs finished within 10 s of each other (vs over a minute of spread without it). Cost was the same (3:24–4:47)
  • Surprise: Without Code Mode, Opus wrote and ran a Python script anyway. In one run the script crashed and auto mode blocked the git checkout undo, and /cost showed 0 lines changed across 53 files. With Code Mode it showed +224/−171 as real diffs, with file history for all 53 files (4:47–6:12)
  • 44 MB log test: Asked for the top 500 type errors by endpoint and status from 200,000 log lines, both modes got the right answer. Code Mode loaded the file into a variable once and queried it like a notebook, while Python re-read the whole file each time, so Code Mode finished faster (6:12–6:53)
Catches
  • Auto mode sees less: The auto-mode safety check reviews the program once, before it runs. So a "find files, then delete them" program gets approved without the check seeing which files got deleted. Your permission rules and hooks still check every action (6:53–8:14)
  • When to use it: Turn it on for big multi-file refactors or large log/data digging. Avoid it for now with Claude in Chrome, Computer Use or the VS Code extension, or where auto mode is your main safety net (8:14–8:55)
