The Sweet Side of the Bitter Lesson — Thariq Shihipar, Independent

AI Engineer · Thariq Shihipar, independent (formerly Anthropic) · uploaded 20 Nov, 1:30 AM IST · 19:08
Verdict: skim from 10:41 — the opening is a light reflection, but the readable-spec-layer demo (10:41–16:35) is a practical idea you can copy.
🔁 Repeat: 'human-in-the-loop review' — seen 50 times before. New here: he argues the fix for losing track of vibe-coded work isn't more review. It's a human-readable "spec" layer of the codebase that you edit directly.
🔁 Repeat: 'software factory' — seen 25 times before. New here: he pairs the "industrial revolution" framing with a "renaissance" one, where craft and taste become what's economically valuable.
What he got wrong this year
  • Right calls: He says he called it early that models would edit and generate video, use HTML to check their own work, and help you plan and learn about your unknowns (0:41–1:12)
  • "Bash is all you need" was wrong: Agents leaned on Bash because of how they were trained early on. He now prefers MCP to CLIs, and code mode, skills and progressive disclosure are all options now (1:27–2:09)
  • "React is all you need" and "diffusion will eat art" were wrong too: Models now write HTML, React, Swift or Figma's own JSON with roughly the same quality. People are writing their own languages, and LLMs make art through code and by driving Blender, Photoshop or Figma. Models didn't force one "alien" way of working on us (2:11–3:58)
Jagged frontier vs smooth interior
  • Industrial revolution and renaissance at once: He says this year was about software factories that made shipping reliable. At the same time, every bit of creativity, utility and "soul" in software is becoming more valuable (4:42–5:53)
  • Smooth interior: Benchmarks track the jagged frontier (to-do app → Slack clone → "build Mario Kart and port it to the Wii"). He cares more about the broad area inside it where models do everything well. He expects the perfect model to need less QA and review from you (5:55–9:17)
  • Land-or-water map eval: In an eval he credits to a post online (the captions garble the name, likely Karpathy), you give a model a latitude/longitude and ask "land or water?", then plot the answers as a map. Opus 4.6 gives a blurry Earth and Opus 5.5 an almost perfect one, a way to see general knowledge rather than benchmark scores (9:18–10:18)
Taking back control: a demo
  • The vibe-coding problem: On his Avatar/Smash-style isometric fighting game, the model made design choices for him (does the rock pass through the summoned wall? what speed, size, charge?). He lost track of what his characters did, got distracted and made less progress (10:41–12:53)
  • Two-part codebase: An engine folder he doesn't read, plus a "spec"/human folder with linted, English-like, well-commented code in real units (meters, not 0.5). This works as a ground truth and a custom scripting language for his game, so he can tweak a move's rock size directly or tab-complete new actions in Cursor. He still asks Claude for new building blocks (13:01–16:35)
  • Renaissance to-do list: He calls for new languages (efficient like Rust but modular, hot-reloadable and readable), new databases, servers, OS interactions and interaction paradigms, and a second look at old HCI research. His point is that we should decide what the future of work looks like (16:42–18:48)

What it takes to set intelligence free — Fabian Hedin, CTO, Lovable

AI Engineer · Fabian Hedin, co-founder & CTO, Lovable · uploaded 19 Nov, 7:30 PM IST · 22:26
Verdict: worth watching — a rare, detailed look at a production long-running-agent architecture, with real numbers (best part 7:48–19:12).
🔁 Repeat: 'coding agents in production' — seen 91 times before. New here: Lovable's own architecture and numbers (over a billion tokens per minute, 700 deploys a day, agents running 10+ hours).
🔁 Repeat: 'sandboxes for agents' — seen 32 times before. New here: full-machine checkpoints including memory and running processes, restored in about 230 ms, with copy-on-write RAM forks.
🔁 Repeat: 'multi-agent / A2A' — seen 30 times before. New here: an honest account of how their 2023 multi-agent framework failed, and per-agent inboxes as the design that works now.
🔁 Repeat: 'AI-generated code validation' — seen 41 times before. New here: little. The inner/outer verification loops are familiar, apart from feeding A/B tests and payment conversions back to the agent.
Lovable's agent history
  • Nearly died building for agents too early: In 2023, "GPT Engineer" made one LLM call per message and could build one-page apps. They then built an elaborate multi-agent framework (main agent spawning front-end/back-end specialists that messaged each other), and it "just made the product worse" (1:43–3:05)
  • Back to simple, then agents again: In late 2024 they went back to one main LLM with small retrieval models, which was fast and reliable. Now agents work, and Lovable runs over a billion tokens per minute through them (3:07–3:53)
  • Outcomes, not code: The platform is a coding agent (browser for verification, GitHub sync), plus cloud basics (DB, auth, storage, security scans, backups, logs), plus business tools (payments, email, SEO, Google/Meta ads, analytics). The agent is in the loop for all of it (4:55–7:42)
Agent runtime for 10-hour runs
  • No time cap: Agents used to be capped at 30 minutes because they weren't reliable. Now there's no limit, and runs can go 10+ hours. Each agent has an inbox that humans, other agents or scheduled jobs drop messages into, and the agent copies them into its own history (its "trajectory") (7:53–9:58)
  • Git-style history: The trajectory is an append-only log where each event points to its parent. That lets them fork parallel agents at any point without copying the shared history, though branches can't be merged. Prompts are built from this log, so compaction can be tuned for each model's context length (a debug slider replays 156 events) (10:22–13:01) (repeat)
  • Stateless workers: Processes save to the history after every tool call, so a 10-hour task survives Lovable's 700 deploys a day (about one every 2 minutes), including urgent Linux kernel security patches (13:04–14:33)
The computer underneath
  • Checkpointed VMs: A "golden checkpoint" (OS, tools, dev server ready to start, including disk, memory and running processes) is copied in about 230 ms. Each turn is checkpointed so idle machines can spin down after about 10 minutes and resume in under a second without dropping in-flight requests. Forks power the "drafts" feature (14:59–16:49)
  • Memory tricks: Copy-on-write RAM makes forks almost free until pages are written. Memory is streamed in so the VM boots before its few hundred MB have arrived (16:56–18:01)
  • Vite rewritten in Rust: By forking Vite and dropping Node.js, previews went from 40 s to 3 s with a 6.5x smaller memory footprint, which makes many parallel agents trying different fixes affordable (18:02–19:12)
  • Verification loops: Inside each turn, the agent checks builds, lint and type errors, runtime errors and a headless browser. Between turns, it uses visitor behaviour, user feedback, automatic A/B tests and payment conversions so it can help optimise the business, not just the code (19:18–21:05) (repeat)
