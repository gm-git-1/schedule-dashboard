Your AI Agent Wants Your Data. Here's How to Lock It Down - Jeff Smith, Oracle

AI Engineer · Jeff Smith, Oracle · uploaded 1 Nov, 4:30 AM IST · 21:40
Verdict: worth watching from 8:13 for the reports-as-tools pattern; skip the swag banter at the start.
🔁 Repeat: 'MCP servers' — seen 36 times before. New here: Oracle's database MCP server exposing your team's vetted reports as two tools instead of letting the agent write SQL.
🔁 Repeat: 'agent security' — seen 27 times before. New here: "deep data security", where the database strips rows from results based on the user's SSO roles.
Why natural language to SQL is risky
  • One SQL interface for everything (repeat): Oracle now stores vectors, graph and other data types next to relational tables, so one MCP server into the database covers RAG over all of it without copying data to eight or nine platforms (1:33–4:10)
  • "If it compiles, ship it": LLM-written queries often run cleanly and still return the wrong data, and agents brute-force the data dictionary to find things, burning tokens and time (7:13–8:13)
Use case 1: reports as tools
  • Vetted reports instead of ad hoc SQL: Load the team's existing reports into the MCP server, each with a description, sample questions and parameters; the agent can pick the wrong report but can't write wrong SQL. 500 reports appear as just two tools, list reports and execute report, so context isn't blown out (8:13–10:15)
  • Teaching the data model: Ad hoc SQL can be switched off entirely, and with the right OAuth scope the tool can show the agent the SQL behind a report so it learns how the data is laid out and one-shots later queries (10:15–11:16)
Use cases 2 and 3: tuning and schema docs
  • Performance tuning on a read-only standby: Point the agent at a Data Guard read-only standby rather than production, and give it a few multi-action tools (for example, generate an AWR performance report or collect optimizer statistics) instead of 15 single-use tools; it advises, a human acts (11:46–14:49)
  • Schema annotations: A schema-info tool returns a compressed JSON dictionary (verbose, medium or slim, with keyword filters) instead of the agent querying every table, and a generate-annotations tool reads your Confluence pages, PDFs and spreadsheets to annotate tables, shown on his Strava workout data (14:49–19:22)
Security and roadmap
  • Deep data security: Agents connect through the user's SSO (for example Azure AD), and the database strips rows the user isn't allowed to see from results before they reach the agent, so an HR manager's agent sees salaries and others' don't. Put security in the database, not just the tools (12:47–13:48) (19:22–20:52)
  • Coming next: MCP apps putting a database GUI inside your agent later this year, skills delivered via tools, and automated RAG pipelines; details at oracle.com/mcp (20:52–21:40)

Everyone Has the Same AI Models. Here's What Sets Agents Apart - Richmond Alake, Oracle

AI Engineer · Richmond Alake, Oracle · uploaded 1 Nov, 12:30 AM IST · 25:47
Verdict: skim from 13:52 for the demo numbers and memory-routing idea; much of the rest is Oracle product tour.
🔁 Repeat: 'agent memory' — seen 16 times before (this is Oracle's second memory talk in two days). New here: framing it as an "intelligence plane" above the control plane, and a fine-tuned small model that routes memories to the right store.
🔁 Repeat: 'decision models' — seen 5 times before.
🔁 Repeat: 'software factory' — seen 14 times before, only briefly mentioned here.
From control plane to intelligence plane
  • Memory basics (repeat): Memory is how an agent retains, reuses, recalls and refines information (his "four Rs"), split into short- and long-term and into semantic, episodic, procedural and working memory (0:31–1:31)
  • Control plane versus intelligence plane: The control plane governs identity, policy, orchestration and auditing; the intelligence plane covers what the agent knows (knowledge), remembers (memory), may see (governance) and how it improves (continual learning) (1:31–2:33) (8:15–8:45)
  • "AF is Midway": In WWII, the small Pearl Harbor codebreaking team, which kept months of intercepts on paper, worked out that "AF" meant Midway while Washington, with the same data, read it differently. His point: everyone has the same models, and information isn't intelligence (4:37–7:43)
Demo: governed versus naive agent
  • Fewer tokens, more accuracy: A finance analyst agent built with an ontology and semantic layer gets answers right 99% of the time using about 32K tokens, versus about 200K for a naive agent; the naive one gets "concentration" and "counterparty" questions wrong (13:52–16:58)
  • What to do now: Treat memory as data, write down your entities and definitions, push entitlements into the data layer and capture memory traces, since those become your fine-tuning data (16:58–18:31)
Oracle's pieces
  • Product tour (mostly repeat): An agent memory Python package that generates context cards, deep data security so the agent inherits the user's row access, a private AI services container for on-prem embeddings, LLMs and rerankers, and a no-code Private Agent Factory (18:00–20:34) (23:10–24:12)
  • Fine-tuned memory routing: In his open-source memory tool, a small open model fine-tuned on his own labelled conversations decides whether each item goes to conversation or workflow memory, replacing hand-written routing code; embeddings and rerankers are the other easy targets for fine-tuning (20:52–23:10)

78% Wanted This AI Feature. Almost Nobody Used It - Supriya Subudhi, Bumble

AI Engineer · Supriya Subudhi, Bumble · uploaded 31 Oct, 2:30 PM IST · 14:44
Verdict: worth watching; short, concrete and a fresh product-manager angle.
🔁 Repeat: 'token costs / AI spend' — seen 14 times before. New here: the product side, with A/B test numbers from a consumer app rather than an engineering team's bill.
The feature
  • AI photo feedback: Bumble (over 20 million monthly users) gave AI-generated tips on how to improve dating-profile photos, based on what the team knows works (1:31–3:02)
Five lessons from the A/B test
  • Users ask for it, then ignore it: 78% of surveyed users said they wanted profile feedback, but only 10–15% used it in the 50/50 test. Adoption rose once the prompt appeared inside existing flows, such as when adding photos or when someone wasn't getting matches (3:02–5:03)
  • The average hides the tail: Top-line results were good (more photos added, more profile edits), but the AI told already-smiling people to smile more. They added guardrails (never comment on things people can't change, like skin colour or height) and evals that read real outputs per segment, gender and language (5:03–7:54)
  • Green dashboard, red bill: The best model was about 10x the cost of a simpler approach, before eval costs; unlike classic ML, GenAI cost grows with every use. Know whether you're chasing short-term revenue or long-term brand value before choosing a budget (7:54–10:37)
  • The win came from the model: Switching to a cheaper model also shrank the results, showing the lift came from the model rather than the idea of feedback; fast eval loops over models and prompts eventually found a cheap option that still worked (10:37–11:49)
  • No global rollout: Regulation kept the feature US-only (she compares Meta's Muse AI, only in the US and Canada), so compliance has to be considered at the start (11:49–13:54)
  • Five questions to ask: Are people using it or just saying they will? Do you read real outputs? Does it pay off after all costs? Can you afford a win on the best model? Which markets can you legally ship in? (13:54–14:44)

When Running Your Own AI Models Beats Paying for APIs - Steven Latré, imec

AI Engineer · Steven Latré, imec · uploaded 31 Oct, 1:30 PM IST · 18:30
Verdict: worth watching from 7:28 if you weigh self-hosting; model names come from auto-captions.
🔁 Repeat: 'open source / local models' — seen 47 times before, and 'inference / serving' 36 times. New here: hard break-even numbers for self-hosting coding agents, including concurrency and harness effects (Revolut's self-hosting talk on 30 Oct covered similar ground from the user side).
The study
  • Who and why: imec, the Belgian semiconductor R&D lab, ran thousands of SWE-Bench Pro runs to measure what moving long-running coding agents from APIs to rented or owned GPUs really costs; owning the stack blows up the design space (model, harness, hardware, CPU-to-GPU balance, KV cache) (0:12–5:28)
  • Setup: Three coding harnesses (Codex and Claude Code among them) across an API baseline and open-weight models of different sizes, each mapped to the smallest hardware that could serve it at scale (5:28–7:28)
Findings
  • Accuracy tiers: Smaller open models like Qwen and DeepSeek resolved about 35–40% of tasks, GLM was around Opus level, and Kimi K3 hit 86% (he suspects some training-set overlap) (7:28–8:40)
  • Cost moves in steps: Qwen and DeepSeek score about the same but DeepSeek needs roughly 4x the hardware; going from GLM to Kimi K3 adds about 20% accuracy for only about 15% more GPU rent (8:40–10:08)
  • Concurrency matters more than accuracy: KV cache per user fills memory fast; even on big hardware, Kimi K3 served only about four concurrent users reliably and was still about 3x slower than the Claude Code API baseline (10:08–12:37)
  • Break-even utilisation: On small systems you need about 89% GPU utilisation to beat APIs (unrealistic); on 8x B200 machines about 15% is enough. GLM-class workloads are the sweet spot, with about 24–25% total-cost savings for coding assistance (12:37–14:31)
  • Harness choice halves the bill: All harnesses reached similar accuracy, but with GLM, Codex generated about half the tokens of the others, halving GPU wall time, which matters once you pay for the GPU (14:31–16:20)
  • Next: A public benchmarking dataset and an alliance bringing software and chip/infrastructure companies together (16:20–18:30)

Voice AI Where One Wrong Question Breaks the Rules - Shiv Indap, Upstart & Brooke Hopkins, Coval

AI Engineer · Shiv Indap (Upstart) and Brooke Hopkins (Coval) · uploaded 31 Oct, 12:30 PM IST · 17:03
Verdict: skim from 7:03 for the judge-agreement story; the loop itself is familiar.
🔁 Repeat: 'evals for agents' — seen 49 times before; 'LLM-as-a-judge' 10 times; 'human-in-the-loop review' 26 times; 'voice agents' 4 times (plus several earlier voice-agent talks). New here: a real lending use case and the climb from 33% to 92% judge–human agreement.
The use case
  • Loan verification calls: About 90% of Upstart applicants are decided instantly; the other 10% get a call asking three things: will income continue for three months, how will you use the funds, and any outstanding obligations like alimony or wage garnishments (1:02–3:04)
  • Compliance traps: If someone says the money is for medical costs, the agent must not ask the amount; "travel to a graduation" needs a follow-up on whose graduation; and it must politely sidestep "when do I get my money" (3:04–4:14)
Human review and judges
  • Outgrowing the spreadsheet: Every call was human-reviewed in a Google Sheet that grew from 5 to 15 ad hoc columns, so they moved to structured review queues in Coval (4:14–5:28)
  • Metrics (repeat): An LLM judge scores each finished call on accuracy, clarity, completeness, policy alignment, correct escalation and CSAT; drop metrics that don't help (5:28–7:03)
  • 33% to 92%: At launch the compliance judge agreed with human reviewers only 33% of the time. Writing down tribal knowledge in the agent, resolving disagreements between human reviewers, and then improving the judge itself got it to 92% (7:03–8:52)
The improvement loop
  • Monitor and route (mostly repeat): Score every live call, catch known failures plus unknown ones via clustering and anomaly detection, and route only flagged calls to the right team (agent, compliance or engineering) (8:52–12:31)
  • Re-simulate before shipping: Fixes are tested with voice-to-voice simulations (accents, background noise, interruptions) before production, then "self-healing" agents propose fixes, but every change sits behind a feature flag and is signed off by engineers or compliance (12:31–17:03)

I Hacked My PC's Power Button So I Can Turn It On From Anywhere (JetKVM + ATX)

Better Stack · Andress · uploaded 31 Oct, 11:35 PM IST · 10:07
Verdict: skip unless you want remote power-on for a home workstation; no AI content.

No repeats: a hardware how-to, unlike anything in history.

What JetKVM is
  • KVM over IP: A deck-of-cards-sized open-source box that captures the PC's HDMI output at up to 1080p/60 fps, acts as keyboard and mouse over USB-C, and streams to your browser over WebRTC with about 30–60 ms latency; because it works at hardware level you can get into the BIOS (0:35–2:38)
  • The ATX Extension Board: JetKVM can't press a power button on its own; the add-on board wires to the motherboard's power-button pins and reads the power LED so the web UI knows if the PC is on (2:38–3:08)
Wiring it
  • Front panel header: On his Gigabyte Z890 board the header is labelled F_PANEL; the ribbon cable splits into power, reset, power-LED and HDD-LED wires. His board's layout differed from JetKVM's assumed standard, so he went pin by pin with the manual (3:08–4:12)
  • Keeping the case button: The ATX board has a second row of pins, so he used Dupont jumpers to keep the case's power button working; the board mounts on a spare PCIe bracket without using a slot (4:12–5:26)
  • Power it from the wall: Four cables (Ethernet, HDMI, USB-C to the PC, extension cable to the ATX board), but power must come from a wall charger, since the PC's USB ports are dead when it's off (5:26–6:32)
Demo
  • Full loop: From a laptop browser he presses power, watches the motherboard logo and Windows login, then shuts down; with JetKVM's free cloud access at app.jetkvm.com he does the same from his phone (6:32–8:44)
  • Tip: If the video sticks on "Connecting", a VPN browser extension blocking WebRTC was the cause (8:44–9:08)

The Best Git Worktree Tool I've Used (Worktrunk)

Better Stack · Josh · uploaded 31 Oct, 1:45 PM IST · 7:14
Verdict: worth watching if you run three or more coding agents at once; otherwise skip.
🔁 Repeat: 'coding agents in production' — seen 54 times before, and 'multi-agent' 16 times. New here: a specific tool, Worktrunk, for running parallel coding agents in Git worktrees (the presenter says Better Stack already did a video on Claude Code's built-in worktrees).
The problem
  • Agents stepping on each other: Two agents in one folder break each other's tests; a Git worktree gives each its own checkout on its own branch, but plain Git needs the branch name typed three times to create one and three commands to clean up. Claude Code's native worktrees fix creation but have no merge command and no status view (0:30–1:26)
Worktrunk in use
  • One command per agent: `wt switch` creates a worktree and starts Claude on a feature in one line; he runs three agents on three branches in three folders (1:26–2:23)
  • `wt list`: Shows every worktree, its branch, how far ahead of main it is and diff size, with a robot icon for a working agent and a speech bubble for one waiting on you (2:23–2:58)
  • `wt merge`: Commits, squashes, rebases onto main, fast-forwards and deletes the worktree, six Git commands in one (2:58–4:00)
  • Integrations: A Rust CLI (MIT or Apache) that installs a small shell function so it can change directory; it hooks into Claude Code's own worktree creation and has plugins for six agent CLIs including Codex, OpenCode and Gemini CLI (3:06–4:31)
Speed tricks and limits
  • Copy-on-write for ignored files: A step command clones node_modules, build caches and env files with copy-on-write, so a 14 GB Rust build folder copies in about 20 seconds using almost no space instead of 2 minutes and 14 GB, and a first build drops from about 68 seconds to 3–4 (the author's numbers). A hash-port filter gives each worktree its own dev-server port (4:31–5:31)
  • Downsides: It's pre-1.0 with "breaking" appearing 80+ times in the changelog, merge conflicts still land on you, copy-on-write only works on filesystems like APFS (plain ext4 gets full copies), and project hooks run shell commands, so read what you approve. With only one agent, native worktrees are enough (5:31–7:14)
