How to Know When an AI Agent Can Work Unsupervised — Evan Kormos, Coinbase

AI Engineer · Evan Kormos, Coinbase · uploaded 20 Oct, 4:30 AM IST · 17:33
Verdict: skim from 12:39 — the node-selection questions and the three-stage rollout are the useful part; the DAG intro is basic.
🔁 Repeat: 'evals for agents' — seen 32 times before. New here: evals plus traces framed as the agent-era replacement for unit tests, run as repeated statistical batches.
🔁 Repeat: 'human-in-the-loop review' — seen 11 times before. New here: a three-stage rollout (supervised, then sampled, then exceptions only) gated by a measured confidence threshold.
🔁 Repeat: 'AI in regulated industries' — seen 7 times before. New here: policy treated as "the original system prompt" for lending and token-listing workflows.
Policy and process
  • Policy is the original system prompt: Written policy (must / may / should) sets how work gets done, especially risk and compliance; he separates the build state (changing policy) from the constantly changing run state (0:00–2:53)
  • Workflows as DAGs: Agents make parallel work worth revisiting: run independent reviews side by side but keep the required gates. Apache Airflow-style DAGs can model commercial lending, listing a token in a region, or regulated software delivery (3:49–5:31)
  • Inside a node is a loop: A code-review node iterates on feedback until work passes (a directed cyclic graph, which he'd manage with LangGraph). Adding agents shifts volume downstream, so operational visibility of bottlenecks matters more than the workflow-authoring tool (5:31–8:59)
The check decides trust
  • The loop is only as good as the check: Inject the DAG state into the agent so it knows where it sits; without a reliable definition of good, more passes don't mean better results (10:00–11:15)
  • Evals as the new confidence mechanism: Agents are probabilistic, so exact output comparison isn't enough: build representative datasets, run evals repeatedly as statistics, and pair them with traces (repeat) (11:15–12:39)
Turning agents on
  • Which nodes an agent should own: In a lending DAG (KYC, financials, credit memo, risk review, docs, decision) ask: can it be checked against policy, run in a bounded loop, be traced, fall back to a human? The final decision stays human-driven (12:39–14:29)
  • Supervised, then sampled, then exceptions: Day one humans verify everything; once measured confidence hits a policy threshold they review a slice while traces check the rest; finally humans handle only exceptions and keep refining datasets. Recipe: deterministic on the outside, adaptive on the inside (repeat) (14:29–16:10)

Smarter Models Killed the Harness. Here's What's Left — Jediah Katz, SpaceXAI

AI Engineer · Jediah Katz, SpaceXAI (ex-Cursor) · uploaded 20 Oct, 12:30 AM IST · 18:15
Verdict: worth watching — 18 minutes with concrete evidence for the "harness is dead" debate and a practical list of what harnesses still own.
🔁 Repeat: 'harness engineering' — seen 23 times before. New here: the data-flywheel argument for why harnesses stop adding coding intelligence, backed by Berkeley and Apple/EPFL studies.
🔁 Repeat: 'software factory' — seen 9 times before. New here: Cursor's internal chain from a bug channel to auto-triage, a cloud-agent fix and a rollout watcher.
🔁 Repeat: 'token costs / AI spend' — seen 4 times before. New here: both harness studies found big cost-per-task gaps even when scores matched.
Is the harness dead?
  • Prompt → context → harness engineer: The job title went from prompt engineer (2023) to context engineer (mid-2025) to harness engineer (2026). He splits the harness into a runtime layer (where the loop runs, how state resumes) and a context/orchestration layer (models, prompts, tools, memory compaction) (repeat) (1:09–2:59)
  • Peak harness and the backlash: Cursor built a browser from scratch with a long-running multi-agent harness called Grind Swarm that took Cursor down once or twice. Then Anthropic's Tariq cut most of Claude Code's system prompt, Garry Tan said only skills would matter, and Cursor removed its small apply-edit model and coding instructions (2:59–5:00)
  • What the research says: A UC Berkeley study ran 7 frontier models across harnesses including Pi, Codex and Claude Code and found no significant score difference on SWE-bench Lite for newer models; an Apple/EPFL study found the same for a dedicated harness on MLE-bench (5:00–6:16)
  • The data flywheel: Harnesses bring harder tasks within reach, more users attempt them, that data reaches the labs, and models absorb the skills, so the harness can delete its own patches (6:16–7:34)
Why the harness still matters
  • New frontiers need new scaffolding: Grok Bot runs long-lived coordinator bots that farm work to worker agents (like a lawyer with paralegals), and there the team is adding prompts and guardrails back for slide decks, travel booking, keeping users updated, acting versus asking, and memory (7:34–10:00)
  • Meta-harness example: Internally a bug posted to a channel is auto-triaged, a cloud agent fixes it and records before/after videos, and after merge a rollouts agent watches production (11:15–12:07)
  • What models can't absorb: Days-long agents need cloud infrastructure, not a laptop that sleeps; agents need scoped permissions so nobody wakes to a catastrophic action or a $10,000 API bill; and tuning cache hit rate, token efficiency and model mix cut Grok Bot's cost and latency with no quality hit (12:07–14:21)
What's next
  • Predictions: Expose less of the harness to users (Hyrum's Law), build primitives like one "subscriptions" tool for waking on Slack posts, red CI or a time of day, log every deterministic "shim" so a bot opens a PR when one stops firing, and expect 90% of agent work to run off the laptop within six months (14:21–17:36)

The Model Swap Workshop: GPT-5.5 vs Kimi vs DeepSeek vs Mistral — Pamela Fox, Microsoft

AI Engineer · Pamela Fox, Microsoft · uploaded 19 Oct, 7:36 PM IST · 51:38
Verdict: worth watching if you ever switch models — concrete side-by-side failures and fixes; skip the setup before 2:23.
🔁 Repeat: 'LLM releases / benchmarks' — seen 36 times before. New here: a side-by-side run of GPT-5.5, Kimi K2.6, DeepSeek V4 Flash and Mistral Large 3 on the same app scenarios rather than leaderboard numbers.
🔁 Repeat: 'evals for agents' — seen 32 times before. New here: Microsoft Research's week-old ASSERT tool that generates test scenarios and judge rubrics from a YAML spec.
Why swap models
  • Have options: New models land constantly and "the US government at any point could cut off access to a model", so apps should be able to point at another model. She deployed GPT-5.5, Kimi K2.6, DeepSeek V4 Flash and Mistral Large 3 on Microsoft Foundry; benchmarks won't tell you how they behave in your scenario (2:23–5:38)
Same prompt, different models
  • Counting letters: Asked to count the E's in "The elderly gentleman eagerly entered the elevator" (13), GPT-5.5 and Kimi got 13, DeepSeek said 6 and Mistral 8; telling Mistral to split into words and count per word fixed it (5:38–8:38)
  • RAG groundedness: With a carpenter-bee-only dataset and a honey-bee question, GPT-5.5, Kimi and DeepSeek said the sources didn't cover honey bees; Mistral answered from its weights and, even after a "say no source provided" prompt, labelled the gap but still gave the info (8:38–13:03)
  • Image input: GPT-5.5 and Kimi named the aurochs, spotted crocodiles (not alligators) and found the $0.58 cheapest plant in a small-font table; Mistral said alligators and picked a $2.30 plant; DeepSeek is text-only. Asking in Spanish made the crocodile test fail (13:03–17:13)
  • Tool calling and loops: On a create-calendar-event call GPT-5.5 added the user as an attendee and DeepSeek wrote "virtual (Microsoft Teams)", showing ambiguous parameter descriptions. On a calculator word problem GPT-5.5 used 1 tool call, DeepSeek 4 (17:13–23:58)
  • LangChain v1 travel agent: GPT-5.5 ran flight and hotel searches in parallel, then a budget check, then activities; Kimi didn't parallelise and made 2 extra calls; Mistral stopped after the searches and never finished (23:58–30:27)
Evaluating and fixing
  • String checks and LLM-as-a-judge: String-compare tool arguments across edge cases (date math, Spanish, slang) and give models a date-math tool. For judges, return pass/fail plus a reason, pre-run app outputs so the judge can change independently, calibrate with domain-expert labels, and expect 200–800 cases for RAG; most models scored 2/3, Mistral 1/3 (30:27–40:07)
  • ASSERT: evals from a spec: Microsoft Research's new ASSERT turns a YAML spec into behaviour categories and generated user scenarios; on the travel agent GPT-5.5 had the fewest violations vs Kimi and DeepSeek. Her advice: never bother with coherence/fluency evals, build custom ones (40:07–45:52)
  • DSPy + GEPA and citations: DSPy's GEPA optimizer wrote a working Mistral prompt for a constrained acrostic list in about 6 minutes (she cites Dropbox and Shopify moving to smaller models this way). Anthropic's citations feature returns cited text blocks for RAG, and the repo now supports Ollama (45:52–51:15)

Buy, Build, Deploy: Using M&A to Drive AI Transformation — Prathik Naidu, Long Lake

AI Engineer · Prathik Naidu, Long Lake · uploaded 19 Oct, 2:30 PM IST · 18:51
Verdict: skim from 9:30 — a business-model pitch with useful numbers, not an engineering talk.
🔁 Repeat: 'AI ROI measurement' — seen 5 times before. New here: value measured as P&L and enterprise value of owned service businesses, not seat or token revenue.
Why selling AI in is hard
  • The walls of outside-in deployment: Security review, 20-year-old systems, driving adoption, seats vs tokens and proving ROI; and real orgs run on veterans' tacit judgement that a vendor integrating with a CRM never sees (0:00–3:45)
  • Value lands in the client's P&L: A $1M/year contract might create $5M/year of EBITDA for the client, about $50M of enterprise value at a 10x multiple, that the vendor never captures. Building an AI-native firm from scratch instead means no customers, brand or specialist hires (3:45–6:27)
The ownership thesis
  • Five advantages that compound: Owning the business gives engineers access to the people doing the work, live data with real answers, incentive alignment, decades of trust and the cash flow to keep investing (6:27–9:30)
  • Service economics: Services is a ~$70 trillion market, but a service firm keeps only about $20 of each extra $100 of revenue (vs ~$80 for software), an "80% marginal tax on growth"; AI breaks the link between labour cost and revenue (9:30–12:16)
  • Long Lake in numbers: About 3 years old, $7.5B raised (Elad Gil, General Catalyst and others), 40 businesses in residential services, architecture and HR, 55 staff, and a $6.3B take-private of Amex GBT corporate travel (12:16–13:20)
Choosing and transforming
  • What to buy: Businesses customers trust with end-to-end outcomes, real human judgement and regulatory accountability, such as handling an urgent leak or a tax decision; they see about 5,000 deals a year and filter hard (13:45–15:20)
  • The J-curve: Invest in deployment, unlock capacity (same output, fewer hours), then put that capacity to work on growth and NPS to reach real P&L impact; the playbook gets faster with each business (15:20–17:30)

Version-Controlled Search: The Web as It Was — Ryan Ahern, Exa

AI Engineer · Ryan Ahern, Exa · uploaded 19 Oct, 1:30 PM IST · 19:13
Verdict: skip if you watch the 27-minute Exa workshop below — same slides and examples; otherwise skim from 6:15.
🔁 Same talk twice: this is a shorter cut of Ryan Ahern's Exa Snapshot workshop posted an hour earlier (below), with the same OpenAI and acquisition examples.
Why Exa
  • Agents broker search now: Agents write verbose queries and run many searches per task; Exa powers Cursor's docs lookups and Gamma's slide data, plus hedge funds, insurers and VCs (repeat) (0:00–3:45)
  • Quality, cost, latency: Exa released its own search benchmark; "dynamic highlights" return only the needed snippets across all results for about 95% fewer tokens than full page text; Exa Agent Ultra handles long-running deep research (repeat) (3:45–6:15)
Exa Snapshot
  • Search the web as it was: 400B+ snapshots searchable by date: fetch a URL as it was at or before a date, or run a whole search as it would have returned then (6:15–8:19)
  • OpenAI revenue example: A 1 Oct snapshot shows reporting (Axios) of a ~$70B annualized run rate; later reports put it closer to $50B net once cloud-provider pass-through is excluded, so you can test whether an agent would have caught the footnote earlier (8:19–10:00)
  • Three backtesting patterns: Enrich a traditional model with versioned data (prices, T&Cs, sentiment), add an agentic feature like an adverse-media scan, or let a fully agentic predictor search while snapshots block look-ahead leakage (11:15–15:00)
  • Overfitting example: A high-scoring workshop feature included "is the company named Dominion?", which is exactly the overfitting a holdout set exposes (16:15–17:30)

Backtest Your Agent Against Yesterday's Web — Ryan Ahern, Exa

AI Engineer · Ryan Ahern, Exa · uploaded 19 Oct, 12:30 PM IST · 26:42
Verdict: skim from 6:17 — watch this or the shorter Exa talk above, not both; the overfitting leaderboard at 23:45 is the fun part.
Exa and Snapshot
  • Exa pitch: AI now searches more than humans; Exa keeps a regenerating benchmark so providers can't train on it, and spans sub-300 ms search to a 20-minute run that found 3,212 video game publishers (repeat) (0:00–6:17)
  • Versioning the whole web: About 100B documents tracking trillions of URLs, with content versioning per URL and version search as of any past date (6:17–7:30)
  • Use cases: The OpenAI $70B vs $50B run-rate reporting, and adverse-media due diligence (an Ed Sheeran example) for insurance, KYC/KYB and partnership checks (7:30–9:15)
Avoiding look-ahead bias
  • Freeze before the outcome: Live search leaks the answer (the deal was announced), so set the snapshot date just before the event and tune features like hiring signals or CEO interviews (10:00–11:45)
  • Publish dates lie: Article publish dates get updated all the time, often for SEO, so they can't be trusted as a feature timestamp (12:30–13:45)
  • Agentic systems too: Backtest agentic features one at a time, or freeze a repo just before a PR was solved to test a coding model without future leakage (13:45–16:15)
Hands-on: predicting acquisitions
  • The game: Write yes/no features scored at 1, 7 and 30 days before an acquisition (+1 hit, −1 false alarm); a CEO/CFO-turnover feature flagged Delivery Hero (acquired) but also Qiagen (not), and AND-combining two features scored better than OR (17:30–21:45)
  • Overfit winners: Winning features were "is this a publicly listed company?" and "is it a company other than Qiagen, Vitris…", pure overfitting, so his takeaway is to always keep a holdout set. Snapshot is an enterprise feature (23:45–26:10)

How the Claude Code Team Reviews Code (REVIEW.md)

Better Stack · Better Stack · uploaded 19 Oct, 3:30 PM IST · 7:57
Verdict: worth watching — 8 minutes of concrete numbers from Anthropic's own process, plus an honest read of the stats.
🔁 Repeat: 'AI-generated code validation' — seen 20 times before. New here: Anthropic's own layered review numbers: revert share down 40% while merged PRs doubled, multi-agent voting reviewer, REVIEW.md.
🔁 Repeat: 'human-in-the-loop review' — seen 11 times before. New here: risk tiers where low-risk PRs from trusted authors need no human, medium need one, highest need two.
🔁 Repeat: 'coding agents in production' — seen 44 times before. New here: the 50-round agent-vs-agent review loop and the 3-round cap.
Why and how much
  • Scale: Claude writes about 90% of Claude Code's code; the main monorepo went from ~2,500 changes a day in May to 30,000+ on its busiest September day. From June to September merged PRs more than doubled while the share reverted fell 40% (0:00–1:21)
  • The goal: Most PRs should merge with at most one human (who can be the author), while reverts and production incidents must not rise (0:50–1:21)
The review layers
  • Before and at the PR: Claude checks its own work (tests, build, screenshot vs design) and a fresh-context subagent reviews the diff; then Claude Code Review runs several bug-finding agents and a separate group votes, posting only issues enough agree on. Repeated mistakes become a lint rule or a CLAUDE.md line (1:21–2:30)
  • REVIEW.md: Code owners write what failure looks like in their area, like docs that lie about a default or config pointing at production instead of staging (2:30–2:57)
  • Security, CI and risk tiers: A blocking security review and CI come next, plus a PR template on how it was tested and how to undo it. A classifier agent assigns a tier: docs or flagged changes from trusted authors need no human, ordinary changes need one, the riskiest paths need two (2:57–4:22)
Keeping the reviewer honest
  • Evals from real incidents: Bugs from incident PRs become daily evals, and noise is tracked by whether people fix or dismiss each comment, since flagging everything would game the score (4:22–5:17)
  • The 50-round loop: One PR went 50+ agent-vs-agent rounds overnight, with 59% of flags on code present since the first review. Now after 3 rounds the author is told to rethink, and re-reviews only look at new changes; one-round passes rose from 65% to 78%, 5+ rounds fell from 9% to 1.5% (5:17–6:01)
  • The catch: Doubling PRs with a 40% lower revert share still means about 20% more reverts in total, and reviews cost about $15–25 each. Worth copying: a short CLAUDE.md, a REVIEW.md, capped rounds, and "you land it, you own it" (6:01–7:40)

Speech Recognition Without the Internet Now Fits on a $10 Chip (Whistle)

Better Stack · Andress, Better Stack · uploaded 19 Oct, 9:55 AM IST · 12:35
Verdict: worth watching if you like edge hardware — a real port with numbers; skip if you only follow agent tooling.
🔁 Repeat: 'voice / speech models' — seen 9 times before. New here: Cactus Compute's 16.9 MB Whistle model squeezed onto a $10 ESP32-S3 with no network.
🔁 Repeat: 'open source / local models' — seen 42 times before. New here: trimming the decoder to 4 layers and int8 math on the chip's vector unit to fit 16 MB flash.
Whistle
  • The demo: An ESP32-S3 with a soldered mic and push button, on a power bank with no Wi-Fi or Bluetooth, changes its LED colour from spoken commands in English and French (0:00–0:50)
  • The model: Released by Cactus Compute on 2 Oct: one 16.9 MB file, 7 languages with auto-detect, word timestamps and embeddings. Whisper Base is 145 MB, and Cactus says Whistle still beats it on LibriSpeech, with a first word in ~11 ms on an M4 Pro; it's built to pair with Needle for audio-to-tool-call (1:15–3:04)
Making it fit
  • Bigger than the chip: The board has 16 MB flash; the 8-layer decoder can be cut while the 8-layer encoder can't. Engram lookup tables take ~5.3 MB and a decoder layer ~0.5 MB, so the 4-layer version fits with 98 KB to spare; Needle plus Whistle would need ~24 MB, so a simple parser replaces Needle (3:04–5:06)
  • How speech becomes text: 16 kHz audio becomes a mel spectrogram in 10 ms slices, convolutions merge them into 80 ms frames (a 2 s command is 25 frames), the encoder attends across the whole clip, and the decoder first emits a language token, then text via cross-attention (5:06–6:46)
Results
  • Speed: Commands took 8.8 s (English) and 11.7 s (French) live, vs ~40 s for Needle 2; the first build took ~24 s until batching frames, using both cores and int8 math on the vector unit brought it to ~10 s on average (7:59–10:32)
  • Accuracy tips: Short phrases ("make it red") were recognised 82–93% of the time vs 44% for a single word; on synthetic voices English colour commands hit ~78%, beating Cactus's full model thanks to keyword biasing and a language-retry rule. Apache 2.0 on Hugging Face (8:40–11:28)
