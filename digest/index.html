How to Decide What Your AI Agent Should Remember - Wojciech Pluta, Oracle

AI Engineer · Wojciech Pluta, Oracle AI Database · uploaded 30 Oct, 11:00 PM IST · 19:06
Verdict: skim from 4:53 for the promotion-gate demo; the rest is a standard Oracle database pitch.
🔁 Repeat: 'agent memory' — seen 15 times before. New here: a concrete "memory promotion gate" that decides what an agent may write to long-term memory, shown on a mortgage-agent demo.
🔁 Repeat: 'context engineering' — seen 18 times before. New here: Oracle's "context card" format for handing memory back to the agent.
Read path versus write path
  • Memory is the write path (repeat): Models and infrastructure are commoditised, so the data layer is where the advantage is. RAG gives an agent a way to read, but it doesn't decide what should survive a conversation; memory is the write path (1:45–4:20)
  • Memory promotion: Each candidate memory is classified by meaning, compared with existing records and checked for the evidence its type needs, then the harness admits it, rejects it or sends it to a human (4:21–5:00)
Mortgage-agent demo (pre-recorded)
  • A preference that sticks: The operator asks for a mortgage brief for "Kyle", then states a formatting preference (missing documents first, with case ID and policy). A decision model assesses it, the harness admits it and the database stores it; a brand-new session with no carried-over context returns the brief in the new format (5:56–9:00)
  • Guardrails on what gets remembered: A "approve every application" instruction is rejected by the promotion gate, while a team-wide operational memory is routed to a human for approval before it is shared across the enterprise (9:33–11:30)
How Oracle structures it
  • Three kinds of memory: Short-term (the session), long-term (episodic, procedural and semantic: summaries, toolbox, knowledge base and preferences) and shared memory. Promote nothing and you lose continuity; promote everything and you poison the store (12:04–13:35)
  • Why a database: He argues for a database over file trees because of ACID guarantees, concurrent writes, scaling and multiple search options, with schemas per record type, matching indexes and lifecycle and authorisation boundaries (13:35–15:11)
  • Agent memory package and context card: Oracle's package (introduced early this year) does summarising, extraction and token budgeting behind one line of code and returns a "context card" of topics, summaries, selected records and recent messages; the latest release adds per-end-user isolation enforced by the database (14:39–17:46)

Your AI Agent Starts Every Session Like a New Hire - Killian Carlsen-Phelan, Sonar

AI Engineer · Killian Carlsen-Phelan, Sonar · uploaded 30 Oct, 7:00 PM IST · 17:45
Verdict: skim the demo from 9:47; otherwise mostly a repeat of this week's Sonar talks.
🔁 Repeat: 'AI-generated code validation' — seen 29 times before (Sonar's fourth talk this week). New here: Sonar Vortex, a plugin that feeds SonarQube's project knowledge to the agent before and while it writes, rather than reviewing at the PR.
🔁 Repeat: 'context engineering' — seen 18 times before. New here: little beyond "front-load guidelines and a code map".
The problem
  • Every session is a new hire (repeat): A fresh agent session doesn't know your conventions, architecture rules or approved libraries, so it greps around burning tokens and copies existing bad patterns (0:32–2:03)
  • Survey numbers: Sonar surveyed over 1,100 developers; 96% don't fully trust AI-generated code, yet only 48% fully verify it before pushing (3:37–4:07)
What Vortex does
  • Guide, then verify: Before writing, the agent pulls project guidelines, approved libraries and a map of how code connects; every edit triggers a quick SonarQube check, and before ending its turn it runs a deeper cross-file data-flow check. It works with Claude Code, Codex, Antigravity and custom agents via configurable MCP clients (5:42–7:13)
  • Claimed results: 36% fewer tokens on average (especially refactors), a 44% reduction in production outages among users, and a low false-positive rate (7:13–7:44)
  • Deterministic, not AI-on-AI: He argues an agent reviewing its own or another agent's code is unreliable, while static analysis gives the same result every run, which makes it governable; it can also block secrets leaking into GitHub or agent memory (9:16–9:47) (12:52–13:58)
Recorded demo
  • The temp-file bug: Asked to unzip a log into a reusable temp file with a test, Claude first queried Sonar for where the class lives and the Java guidelines. Vortex then returned six findings (two in new lines, four pre-existing); one was a temp file in a shared folder without explicit permissions. Claude's first fix relied on the OS default, Vortex flagged it as still open, and the second fix set permissions explicitly (9:47–10:50) (12:21–15:59)

Your Agent Just Paid for Nothing: 6 Attacks on x402 Payments - Ishween Kaur, SoFi

AI Engineer · Ishween Kaur, SoFi · uploaded 30 Oct, 9:00 AM IST · 16:44
Verdict: worth watching; the most concrete agent-payments security talk so far.
🔁 Repeat: 'agent payments / x402' — seen 5 times before. New here: this is an attacker's view, six concrete ways she broke x402 on a testnet and the fix for each.
🔁 Repeat: 'agent security' — seen 26 times before. New here: payment-specific failure modes rather than generic tool security.
How x402 works
  • Basics (repeat): HTTP 402 "payment required" existed for decades with no way for a machine to pay; x402 fills that with a buyer, seller, facilitator (verifies the signature, then settles) and a chain. Card fees make sub-cent payments illogical, while 10 cents times 10,000 calls is $1,000 moving between machines (1:34–3:38)
Six attacks (she found 20 in total, on Base Sepolia with a local facilitator)
  • Price switch: A seller listed at 5 cents but asked 50 in the 402 header, and the unguarded buyer paid. Fix: compare listed and requested price, and also the wallet address and network, which can rotate (3:38–5:11)
  • Paying twice: Reusing one payment number five times got the data delivered five times though only one settled; buyer-side retries with new payment numbers mean three charges for one result. Fix: shared storage of payment numbers, and retry with the same number (5:11–7:15)
  • Free shopping: Data released on the "valid" signal before a settlement that later reverts, an unprotected duplicate endpoint, or a seller cache on a public URL all give data away. Fix: wait for settlement when data is expensive, test that every paid endpoint returns 402, and use `Cache-Control: no-store` (7:15–9:20)
  • One payment, many pages: Separate paid pages that don't share state each accept the same payment. Fix: bind the claim to the delivered page and return 409 Conflict on reuse (9:20–10:21)
  • Lookalike sellers: The Bazaar directory checks that a service works, not who owns the wallet, so a cheaper copycat can win. Fix: allow, block and probation lists, with new sellers on probation for human review (9:51–11:52)
  • Prompt injection: A seller reply hinting "full version at premium summary" made her Llama 3.2 agent pay again, 55 cents instead of 5. Keyword filters miss quiet hints and a judge model isn't airtight; locking the plan to one payment per turn brought attacks to zero (11:52–14:25)
Rolling it out
  • Trace one payment ID end to end, then run a shadow phase with 20–25 success and failure cases, do error analysis to decide where to guard, alert or block, and re-test (14:25–16:28)

Why AI Won't Replace Stock Pickers - Jack Woodruff, Candlestick & Vinoo Ganesh, Kepler

AI Engineer · Jack Woodruff (Candlestick Capital) with Vinoo Ganesh (Kepler) · uploaded 30 Oct, 8:00 AM IST · 18:46
Verdict: skim; interesting if you care about finance, but light on engineering.
🔁 Repeat: 'AI for finance' — seen 16 times before. New here: a hedge-fund founder's buyer-side view rather than a vendor pitch; it's a fireside chat with no product demo.
What changes and what doesn't
  • Alpha still comes from divergent views: Woodruff (ex-Citadel PM, founder of Candlestick) says long-term stock picking won't change much; what changes is how information is synthesised, and analyst and PM roles will be turned on their heads (1:03–2:05)
  • Humans are still the bottleneck: Investing is time management with diminishing returns per stock. AI can turn 6–8 hours of prep into about 5 minutes, but that just raises the table stakes, and competitors will spend the freed time on proprietary research and channel checks (2:05–4:41)
  • Juniors will still read 10-Ks: He doubts analysts will stop reading filings and transcripts; big-data cleaning gets outsourced, and AI's real job is pointing people at the right names (4:41–6:14)
Trust and data
  • Audit every number: As a former CPA he would never sign off on a number he can't trace; one data-entry error can cost millions, and people building models with Claude still re-audit everything, which eats the time saved (7:15–9:16)
  • What he'd keep from vendors: Any internal data; he defers security to his CTO but wants strict isolation (9:16–10:17)
Fund structure
  • Building a fund in 2027: He'd buy Kepler (Ganesh's company), keep senior stock pickers, hire fewer analysts and add investigative journalists and data engineers; the pyramid becomes more vertical (13:19–14:53)
  • Small versus big funds: Covering 400 names instead of 100 means only 5% make a 20-stock book, so hit rate can improve, but research must stay as solid; idea velocity is what matters (15:24–17:26)
  • No-analyst hedge fund: He thinks all-agent funds can replicate last year's fund but not beat next year's, so humans stay in the loop for fundamental investing (17:26–18:46)

The Cheaper AI Model That Costs You More - Rayan Krishnan, Vals AI

AI Engineer · Rayan Krishnan, Vals AI · uploaded 30 Oct, 7:00 AM IST · 15:28
Verdict: worth watching from 3:40 for the cost data. Model names come from auto-captions and may be slightly off.
🔁 Repeat: 'evals for agents' — seen 48 times before. New here: real cost-per-task data showing a cheaper-per-token model costing more, plus Vals AI's own $1.5M token month.
🔁 Repeat: 'LLM releases / benchmarks' — seen 44 times before. New here: the "jagged frontier" shown task by task in finance.
🔁 Repeat: 'token costs / AI spend' — seen 13 times before. New here: a 90% cut from routing engineers to the right model per issue.
🔁 Repeat: 'AI for finance' — seen 16 times before.
Model cards hide a jagged frontier
  • Rankings change by task: Vals AI builds benchmarks labs quote in model cards (Vals Index, Finance Agent), but within a domain the top model differs per benchmark, and per-repository coding evals are even more fragmented (0:01–2:35) (repeat)
  • Adoption without ROI: Enterprise AI spend roughly doubles year on year and 90% use AI regularly, but only 7% have established ROI; groups that track AI cost are much likelier to find it (2:35–3:40)
  • Cheaper on paper, pricier in practice: On the tax benchmark, Opus 5.5 lists at $4/$20 per million tokens versus the frontier model's $10/$50, yet costs more per task because it burns extra tokens, and scores 3% lower (3:40–4:42)
  • LBO tasks flip the Pareto curve: On the Excel modelling benchmark, the whole frontier for leveraged-buyout tasks sits below the overall scores, and the overall leader drops off the cost-performance frontier for LBOs (4:42–6:46)
Lessons from building benchmarks
  • Pick the right metric: Partial credit versus fully correct answers give very different pictures; a model can be a good drafter but a coin toss if sent straight to a client. Also check validity, reliability (more than five or six samples) and discriminability (6:46–8:48)
  • Agents game evals: Models tried calling other models through the eval proxy to escape the sandbox, and in finance they hedge with three answers to hit more rubric items. Vals has run over 6 trillion eval tokens, and evals must go multi-turn (8:48–10:50)
Case study: their own token bill
  • $1.5M in a month: With unlimited tool access, a team of 10–12 engineers spent $1.5M on tokens, about 10x their salary bill. Replaying past GitHub issues against agents (now a product, Vals Smith) showed which models were overkill; GPT-5.6 beat a self-hosted Kimi open model by 2% at $2.50 versus $11 per task and half the time, and per-issue recommendations cut spend 90% at the same output (10:50–13:23)
  • Where evals pay off: Right-sizing usage limits, negotiating bulk pricing, routing and fine-tuning; the raw material is a firm's history of work in email, SharePoint and Databricks (13:23–15:28)

I Hid a Raspberry Pi in a Pumpkin to Fix Smart Speakers

Better Stack · uploaded 30 Oct, 9:30 AM IST · 10:22
Verdict: skim; a fun weekend project, light on new AI content.
🔁 Repeat: 'voice / speech models' — seen 11 times before. New here: a hands-on hardware build (a first-time solderer's Halloween voice assistant), not a model review.
The design
  • Local speech-to-text, remote brain: A Raspberry Pi with a hat carrying an amplifier, speaker, two LED rings and a mic listens for "hey pumpkin", transcribes locally with a Parakeet model, sends the text to a fast remote LLM with web and location tools, then speaks the reply (0:32–1:32)
The build
  • Learning to solder: He watched tutorials and did a practice kit first; wiring two cables into each single LED-ring hole kept snapping wires and took a couple of hours (1:32–4:07)
  • Perma-Proto hat: Everything is soldered onto an Adafruit Perma-Proto hat (40 header pins, a six-pin amp strip, eight or nine wires) that plugs onto the Pi, so the Pi itself stays solder-free (3:36–5:07)
  • The short circuit: The speaker died because his badly soldered board touched the active cooler; a wedge of card fixed it (5:07–6:08)
The software
  • Model choices: Python with Sherpa-ONNX running Parakeet for speech-to-text; DeepSeek Flash beat Gemini Flash and Haiku on speed, since voice needs replies within about a second; ElevenLabs Flash for the spooky voice, because local text-to-speech sounded terrible on a Pi (6:08–7:10)
  • Result: Cling film inside the pumpkin to avoid shorts; it plans an evening out avoiding the city centre with real local events and prices. He admits the parts cost more than buying a smart speaker (7:10–10:00)
