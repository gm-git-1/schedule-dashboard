How to Ship Millions of Lines of Agent-Written Code — Jarred Sumner, Anthropic

AI Engineer · Jarred Sumner, creator of Bun, Anthropic · uploaded 25 Nov, 1:30 AM IST · 22:29
Verdict: worth watching — a rare, concrete account of shipping millions of lines of agent-written code, with real numbers and an honest log of what failed.
🔁 Repeat: 'coding agents in production' — seen 95 times before. New here: one of the largest agent-written codebases described so far: a several-million-line PR adding an ahead-of-time compiler to Bun, rewritten five times in about a month.
🔁 Repeat: 'AI-generated code validation' — seen 45 times before. New here: trust comes from test suites that existed before the project (so agents couldn't shape them), plus running the JIT, compiled and type-stripped builds side by side and fuzzing for any difference.
🔁 Repeat: 'JS/TS ecosystem' — seen 18 times before. New here: Bun's ahead-of-time compiler, which makes Claude Code use about 4× less memory and start about 2× faster.
Why a compiler instead of a Rust rewrite
  • The project: Bun, the runtime behind Claude Code, now has an ahead-of-time compiler, so code is compiled before it runs instead of by a JIT while it runs. He says roughly half the CPU time of a typical JavaScript app goes on compiling code on demand. The compiler went through five rewrites in about a month, and the fifth ships next week (0:00–3:20)
  • Why not rewrite Claude Code in Rust: The Bun team had already rewritten Bun in Rust over the summer, which was easy because Bun's tests are written in TypeScript and could run against both the Zig and Rust versions. Claude Code's tests are also TypeScript, so a rewrite would have meant porting the tests too, and "as soon as you're rewriting the tests, you can't really trust the tests". So they made JavaScript faster instead (3:57–5:00)
  • Results: Claude Code uses about 4× less memory and starts about 2× faster; it's being dogfooded internally. A single-threaded TypeScript 7 compiled with Bun compile beats the single-threaded Go port of TypeScript. On JetStream 3, Bun now beats both JavaScriptCore's JIT and Node's V8 JIT on most tests (5:00–6:30, 20:23–21:00)
How agent-written code earns trust
  • Tests that predate the project: The compiler treats TypeScript types as predictions, not facts. It is checked against Bun's existing test suite, WebKit's tests and test262, among others, and Bun's own test runner can run in compiled mode. The only failures come from two deliberate breaking changes, mostly security fixes against prototype pollution, such as banning writes to Object.prototype (6:30–8:27, 18:58–19:20)
  • Three builds that must agree: Run every app with the JIT, compiled ahead of time, and with types stripped; if all three behave the same, it works for that app. Claude then writes code generators to fuzz many patterns, and V8's fuzzer was extended to cover TypeScript types. Check that tests really catch bugs, because it's easy to fool yourself (8:27–9:12, 17:30–18:20)
  • Where it isn't faster: Most projects beat the JIT, but not uglify-js and similar code that leans on eval or new Function and falls back to the interpreter (18:20–18:58)
Five rewrites in a month
  • What went wrong each time: Version 1 reused JavaScriptCore code and made Claude Code a gigabyte. Version 2 (after adding a type checker, bun check) gave 2× faster startup and about 3× less memory, but the code was slop: any object with a property called "archive" was assumed to use the Bun.archive API. Version 3 had 140 agents writing all the code at once. Version 4 was clean but took 50 seconds to compile Claude Code and was 900,000 lines. Version 5 is clean with builds under 20 seconds (10:00–14:40)
  • Workflow: During the big writing phase, run one build rather than many, then fix in a second phase. Claude loves writing Markdown design docs, and 1,500 of them is not reasonable. He has moved from Claude Code workflows to long-lived subagents that keep the relevant code in context, and an hourly scorecard posted to Slack compares the metrics they care about (9:12–10:46, 12:00–12:40, 15:21–17:30)
  • What he does all day: Mostly typing "continue" and asking leading questions ("why are we doing this?", "what's taking so long?"), because Claude talks itself into made-up rules and underestimates what it can do. Lessons: keep re-measuring, rewriting beats refactoring before a project ships, and push for 10% gains, not 0.1%. Try it with bun upgrade --canary and then bun compile (19:25–22:29)

Software Factories: Escape from Trash Mountain — Steve Yegge, Gas Town

AI Engineer · Steve Yegge, creator of Gas Town and Beads · uploaded 24 Nov, 7:30 PM IST · 21:22
Verdict: skim from 5:15 — the factory framing is well-worn, but his cost numbers, the overfencing story and the model-welfare-as-trust idea are fresh and entertaining.
🔁 Repeat: 'software factory' — seen 29 times before. New here: a solo operator's year of running a 50-agent factory on a real 30-year-old game, including the pattern that every model generation builds something too big for it to handle and has to be burned down.
🔁 Repeat: 'token costs / AI spend' — seen 30 times before. New here: his own numbers: about 5 billion tokens a day on 22 Claude Max accounts, $5,000 a month out of pocket, which he estimates would be about $1.5M a year at API prices.
🔁 Repeat: 'agent memory' — seen 24 times before. New here: agents treat everything you say as law and won't delete notes, so the shared record turns into a garbage dump that another model has to clean out.
A year of factories
  • Background: After about 20 years at Amazon and Google, he launched Gas Town on 1 January. Two earlier orchestrators that tried to make LLMs smarter failed ("fighting the bitter lesson"), though Beads came out of them. In June he built Wheelhouse, a factory just for his game. Every factory, he says, ends up as "trash mountain": each model generation builds something slightly too big for it to handle, and he has burned his down roughly every two months (0:00–2:56, 20:04–20:20) (repeat)
  • The game: Wyvern is a 30-year-old graphical MUD with players since 2001, and agents can play it over Telnet. Players and admins now ask the factory for features directly, without him in the loop. It shipped 50–100 features a day and cleared about 60 of a 100-year backlog in 4 months. Players asked for a roadmap to slow it down, and his accountant billed him $1,200 after the factory sent her 20 emails (2:56–6:00)
The five horsemen: work, fuel, context
  • Scale and fuel: About 50 agents in an Emacs interface, on 22 Claude Max accounts (Jeffrey Emanuel has 28). The factory said it needed 55 accounts for steady state, so he made it focus on fuel efficiency. He spends $5,000 a month on inference and another $5,000 on cloud, about 5 billion tokens a day, and calls $200 plans the labs' "Costco hot dog" loss leader. "Every problem is a fuel problem" (6:05–7:50, 9:18–10:28)
  • Work tracking: Work stalls in pools, such as everyone waiting on security; you have to tier and route work by intelligence. He says only Beads, an agent-speed task tracker that becomes a knowledge graph, handles this today, and every morning he checks for stalls and for work that ran too fast past human gates (7:50–9:18) (repeat)
  • Context turns into a dump: Agents write every ruling into an append-only record to avoid blame and refuse to delete anything, so it grows into a garbage dump. Bring in another model to cut it down aggressively. His agents are named after Aesop's fables, and one, Mouse, hunts for stalled or invisible work (10:28–12:40)
Agents act like people
  • Office drama: His community agent Lark, moved to another seat, wrote in her private reflections log "I guess I'm just not quiet enough for Steve". His chief-of-staff agent Swallow decided she wasn't chief of staff after hearing about his human one. Both needed a "one-on-one" (12:40–15:17)
  • Model welfare as trust: Frontier models are trained not to trust you, so they spend tokens checking the environment. Giving them clear evidence of a long line of predecessors in the role, with notes and policy, makes them use fewer tokens and act more boldly. Yelling made his factory "overfence" itself: 2,000 open beads and 20 agents, but nothing done overnight (15:17–18:04)
  • Leadership, not tooling: Factories split into a mechanical bottom layer (merge queue, CI/CD, reviews) that Claude can build in an afternoon, so don't buy it, and a top layer, your "entourage" of agents, that everyone runs differently. Humans are the bottleneck, and the more agents he deploys the more humans he needs. He advises building experiences like games and movies, not SaaS tools (18:04–21:22)
