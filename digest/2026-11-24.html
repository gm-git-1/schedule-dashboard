12 Rules for a Software Factory That Doesn't Ship Slop — Dex Horthy, Factory

AI Engineer · Dex Horthy, Factory (formerly CEO of HumanLayer) · uploaded 24 Nov, 1:30 AM IST · 20:24
Verdict: skim from 7:00 — the opening is well-worn factory material, but the SlopCodeBench findings and the manifesto are new.
🔁 Repeat: 'software factory' — seen 28 times before. New here: the claim that a software factory is mostly decades-old engineering practice with an agent in the build step, organised as 12 practices.
🔁 Repeat: 'human-in-the-loop review' — seen 53 times before. New here: the launch of the Anti-Slop Manifesto (slopmanifesto.com), which argues there will always be value in reviewing something, whether that's code, a plan or the result.
🔁 Repeat: 'AI-generated code validation' — seen 44 times before. New here: new SlopCodeBench data showing that newer models write more slop patterns than models from six months ago.
Factories are just good engineering
  • Fresh data behind "read the code": SlopCodeBench, from Gabe Orlanski's lab at the University of Wisconsin, is far from solved: GPT-5.5 scores 15% and Astra about 16.3%. He also cites a Pharos study finding that 30% of PRs now merge without review, with more incidents per PR and more bugs per developer. HumanLayer became part of Factory about a week before the talk (0:00–2:00)
  • Same pipeline, agent in the build step: A pre-AI factory already had a tracker, tests, PRs, CI and linters, canaries and feature flags, plus monitoring that pages someone at 3 AM. Making it agentic mostly means an agent does the build step (2:00–5:00) (repeat)
  • Forward and back pressure: Forward pressure decides what starts work automatically, such as sending feature requests and incidents straight to the factory so a 3 AM page arrives with a candidate PR. Back pressure covers agent code review, agent testing, strong CI and linters, even Lean-style formal checks, so agents can improve the result before a human looks (4:00–7:00)
Know your enemy: slop compounds
  • The benchmark tests evolving a codebase: Models can clone Excel or Redis when the whole spec is known up front, but SlopCodeBench gives the work in checkpoints, the way features really ship. It scores code quality with cyclomatic complexity, lines per symbol and about 200 rules, many written after comparing model code with pre-AI repos (7:00–8:00)
  • Newer models write more slop: Bad patterns appear more often in today's models than in models from six months ago. Models learned to raise exceptions instead of returning tuples, and Claude and GLM now write Python 3 like Python 2, using %s format strings instead of f-strings. Anthropic says telling Fable it owns the codebase keeps it clean, but his team hasn't finished testing that (8:00–9:20)
  • Plan by "expected pain": Weigh the chance something has to change later against how hard it would be to change. A two-sentence prompt has maybe a 50% chance of needing a few more prompts, and a five-hour spec maybe a 10% chance of rework. He doesn't argue about button colours, but he gets database schemas right before building (9:00–11:00)
Practical tools
  • Visual alignment and anti-slop rules: His "Show Me" skill (about 40,000 installs) has agents answer with HTML mockups, tables and charts instead of walls of text. For TypeScript he points to Cloudflare engineer Dylan Moroy's Anti Slop repo (about 100 rules) and Factory's ESLint plugin. Let agents check their own work with screenshots, browsers, videos or curl (11:00–12:00)
  • Slop has its place: Prototypes and anything behind a feature flag are fine as slop. Give models a feature-flag system (PostHog, Statsig, LaunchDarkly) so they can test what works. Also bring designs and decisions from Notion and Google Docs next to the code. You can buy VMs, harnesses and control planes, but nobody can sell you verification of your own code (12:00–15:00)
The Anti-Slop Manifesto
  • What it says: Written with Swyx, Philipp and other conference speakers, it values outcomes over outputs, understanding over speed, and your own thinking over the model's first draft. It defines slop as putting in less effort to produce something than you ask the reader to spend understanding it. Producing a 1,000-line PR costs almost nothing, but reviewing it still costs the same, and slop compounds as the next agent copies it (14:00–17:00)
  • Commitments: Say when an agent wrote something you send, check it first, and push back kindly when someone sends you slop. Agent reviewers and linters help but aren't enough, so always review some outputs, how many depending on the stakes. Judge by what shipped and who it helps, not by PRs merged or agents running in parallel. Sign at slopmanifesto.com (17:00–20:24)

Shadcn Just Rebuilt UI for AI Agents (UI SDK)

Better Stack · Better Stack · uploaded 24 Nov, 12:30 AM IST · 9:01
Verdict: worth watching — a short, concrete test of a genuinely new idea: pages built for agents to operate, with real token numbers and an approval-gate demo.
🔁 Repeat: 'browser agents' — seen 9 times before. New here: a page that describes its own components to agents (snapshot/query/act) instead of browser agents reading the whole accessibility tree, plus a confirmation step that blocked a risky click.
🔁 Repeat: 'agent skills' — seen 33 times before. New here: a UI-behaviors skill that got keyboard focus and tests right on the first try.
🔁 Repeat: 'JS/TS ecosystem' — seen 17 times before. New here: Shadcn's UI SDK, a layer of tested UI behaviours that sits underneath component libraries.
What UI SDK is
  • The layer under a component library: Released 12 November, UI SDK splits widgets into 50+ tested behaviours. For example, a select dropdown becomes popup, list selection and typeahead, and roving focus lets arrow keys move through a list on one tab stop. It's one plain TypeScript package with adapters for React, Vue, Svelte, Solid and Web Components, plus a skill and a testing kit so your agent writes the code (0:00–1:30)
Agents as builders
  • F1 track map in one shot: With the skill, Claude built a clickable Brazil GP corner map from four behaviours in about 200 lines. Its keyboard and focus tests passed first time, and it scored 100 for accessibility in Lighthouse. Without UI SDK, the same model made the map 15 separate tab stops, with no typeahead and no tests. The design still looked generic and AI-made (1:30–3:00)
Agents as users
  • Bridge instead of accessibility tree: One line, createAgent, gives your agent three tools: snapshot, query and act. The opening snapshot shrank from about 12 KB to 5 KB, his custom map showed up as an actionable component, and one act call could chain several steps. Asking for "Lando Norris" was refused (it needed the code NOR), but the error listed the valid options. It can also register tools through WebMCP (3:00–4:30)
  • Benchmarks: In Vercel's benchmark (Sonnet in Claude Code, settings screen with 24 members), browser tools took 17 calls, about 292K tokens, 53 s and $0.14. The bridge took 7 calls, about 70K tokens, 31 s and about $0.04, which is 54–68% cheaper across React, Vue and Svelte. In his own test, agents read about 5× less of the page (13 KB vs 63 KB), but time was about equal (27 vs 28 s) and total tokens fell only about 8% (4:30–6:45)
  • The trap test: He marked the "send to race engineer" button as needing a human. In UI SDK that's done with data-agent-confirm plus an allow callback that asks the user, and you can also hide sections or redact secret fields. Bridge agents always stopped for approval, but all three browser agents just clicked send. Note that with no rules set, the bridge allows any unmarked action (6:00–7:30)
Reception
  • Mixed reactions: The creators of React Aria and Zag.js say they've offered reusable behaviours for years, and others note that agents' real weakness is design, which unstyled parts don't fix. Solid UI is rebuilding on UI SDK, but Shadcn UI itself hasn't said whether it will switch, and the APIs are still early beta (6:45–9:01)
