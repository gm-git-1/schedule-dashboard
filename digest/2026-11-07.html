Your AI Agent Is Hiding Its Mistakes From You - Ben Holmes, Warp

AI Engineer · Ben Holmes, Warp · uploaded 7 Nov, 3:30 AM IST · 19:19
Verdict: worth watching — actionable self-improvement loop with a try-at-home skill, not just "agents should learn."
🔁 Repeat: 'self-improving agents' — seen 20 times before, 'coding agents in production' 64 times, 'agent observability' 33 times, 'software factory' 17 times, 'agent skills' 17 times and 'LLM-as-a-judge' 15 times. New here: Warp's concrete loop—centralize team agent traces (transcript + tool calls + PR diffs), LLM-as-judge rubrics for redundant tests / verbosity / efficiency, a daily cron agent that opens skill/config PRs, and Skill Doctor (warp.dev/skilldoctor) you can run on local Claude Code/Codex history; the key failure mode is agents quietly working around broken instructions without telling you.
Factory engineering loop
  • Beyond the assembly line: Holmes frames software factories as the SDLC wheel (triage → spec → implement → computer-use screenshots → adversarial review) plus "factory engineering"—meta-work on skills, architecture and static analysis that makes the wheel run 0:55–3:12
  • Self-improvement wheel: Agents review past conversations → scoring agents grade against rubrics (efficiency, code quality, test coverage) → a cron agent finds failure patterns and suggests skill/config PRs, then you re-score 2:40–3:24
What to capture and score
  • Centralize traces: Local Claude/Codex folders work for single-player; some teams zip everyone's `.claude` into S3; cloud runners / Warp Docker sandboxes get team traces for free—capture transcript, tool/MCP/FS calls, and outputs (diffs/PRs) 3:24–6:12
  • Three scorers: Redundant tests (~40% of room raised hands; Warp's team was ~100%), verbosity (comments + PR summaries that slow review), and efficiency—because agents persist around broken skills (e.g. probing ports) and only look "2 minutes slower" 6:15–9:14
  • Rubrics as markdown skills: Efficiency rubric labels success/fail (≈0.4/0.2 = fail); keep definitions short and grow them; grade on PR-merge, sample or full 9:16–12:15
Skill Doctor and continuous PRs
  • One-shot home run: Skill Doctor crawls Claude/Codex history, grades in batches, and proposes skill patches (e.g. e2e testing skill that finds a free port first; more prescriptive changelog skill) 13:46–16:45
  • Dashboard + inbox: Score time series attribute skill merges to efficiency lifts; Warp Factories continuously scores and opens reviewable self-improvement PRs (e.g. triage skill missing sub-agent spawn config wasting tool calls) 16:47–19:14

Your Old Prompts Are Making Claude Worse - Lance Martin, Anthropic

AI Engineer · Lance Martin, Anthropic · uploaded 7 Nov, 2:30 AM IST · 1:04:02
Verdict: worth watching (skim Q&A after ~24:25 unless you care about eval grading / long-task hill climbing) — densest practical Anthropic cost/quality checklist in this batch.
🔁 Repeat: 'evals for agents' — seen 60 times before, 'coding agents in production' 64 times, 'harness engineering' 32 times, 'token costs / AI spend' 20 times and 'Claude Managed Agents' 5 times. New here: concrete Claude Code skills—`checkup prompt audit` / `Claude API prompt audit` (strip think-step-by-step / verification rituals / contradictory rules that hurt frontier models), prompt-cache audits cutting internal harness cost up to 72% with no quality loss, `Claude API hill climb` with train/test split to catch overfitting, a Claude API skill hill-climbed from 66%, stronger-model-at-lower-effort cutting cost ~90% while improving, and Managed Agents' brain/hands/session-log recoverability for day-long runs. Main talk ~24 min; rest is Q&A.
You're inside the Pareto frontier
  • Misconfig, not model: Cost vs quality looks like a frontier (Haiku→Sonnet→Opus→…), but many apps sit inside it because of small misconfigurations Martin walks through how to fix 0:00–1:32
  • Prompt debt: Old habits—"think step by step", verification rituals, "be maximally thorough", scratchpads—raise cost and can confuse instruction-following frontier models; contradictory rules that older models ignored now trip them 1:32–3:20
  • Run prompt audit: In Claude Code, `checkup prompt audit` (local config) or `Claude API prompt audit` (API code) strip anti-patterns; on a 50-ticket support eval, migrating Opus 4.8→5.5 plus audit beat migration alone on both cost and score 3:20–5:30
Cache and climb
  • Prompt cache is prefix-strict: Multi-turn agents should hit cache (~1/10 token price); any byte change busts it—track hit rate in Claude console / Claude Code religiously; Anthropic saw up to 72% cost cuts on internal eval harnesses with no meaningful performance change just by fixing cache layout 5:30–8:45
  • Climbable evals: Good evals rise with model size and thinking budget, aren't saturated, and have low run-run variance; ambiguous tasks fake a ceiling 8:45–11:47
  • Hill climb without overfitting: `Claude API hill climb` splits train/test, only reflects on train failures, and flags train↑/test-flat as overfitting; Claude API skill went 66%→much higher by iterating skill text against docs 11:47–16:30
  • Stronger @ lower effort: Moving up a model at lower effort often beats a smaller model at high effort—fewer tokens, better answers; baked into the hill-climber (example ~90% cost cut) 16:30–18:50
Harnesses for day-long agents
  • Brain ≠ hands: Claude Managed Agents decouple harness (brain), sandboxes (hands), and an append-only recoverable session log so either dying mid-run can restart without losing state—aimed at day-scale autonomous work 18:50–24:10

New here: crisp numbers on why AI labs still ship Electron (Claude/OpenAI Codex/Orca/T3/Kimi)—Claude's Electron Framework is 286 MB of 618 MB; 22 Electron apps ≈ 6.5 GB of Chromium copies; Claude idle ~600 MB / 11 processes; native ChatGPT Mac was 159 MB vs Electron Codex app 1.7 GB; empty Tauri ~5 MB vs Electron ~268 MB—and why consistency + code reuse still win over Tauri/Wails/native.
Why the hate
  • A Chromium per app: Every Electron app ships its own Chromium; fixes only land when each app updates; a past macOS update lagged the system until every app shipped Electron's fix 0:00–2:58
  • Alternatives' tradeoffs: Native = N platform teams (1Password had four before Electron); Tauri/Wails use OS webview (Safari/WebKitGTK/Edge)—tiny binaries but engine differs per machine and you can't ship engine fixes (Tauri Linux/Nvidia notes) 1:30–4:28
Why AI companies still pick it
  • Consistency: Slack moved off Safari webview after old macOS bugs left them stuck; shipping Chromium means you fix and ship yourself—Electro Bun and Tauri Free alpha even add optional bundled Chromium 3:00–4:28
  • Reuse: Boris Cherny on Claude Code sharing web/desktop; OpenAI Codex app shares code with CLI + VS Code extension; agents writing three native apps still means 3× bugs/support 4:28–5:03

Ghostty's Creator Just Launched a New Terminal (Rex)

Better Stack · Better Stack · uploaded 6 Nov, 12:30 PM IST · 4:17
Verdict: worth watching — short clear Rex vs tmux/Hurder explainer if you run agents across Macs.
🔁 Repeat: 'dev tools' — seen 13 times before and 'coding agents in production' 64 times. New here: Mitchell Hashimoto's Rex—Ghostty-engine terminal with a background server (not tmux), native Tailscale multi-host sessions so a MacBook can sleep while Claude keeps running on a Mac mini, Mac-only closed-source for now, vs tmux (SSH-anywhere) and Hurder (OSS, Win/Linux, separate terminal).
Why not just Ghostty + tmux
  • Quit kills children: Normal terminals own their processes; tmux detaches but is its own terminal (redraw, its own scroll/select/keys)—Hashimoto said on Changelog (Dec 2024) that makes UX worse 0:00–1:31
  • Rex = Ghostty UI + persistent server: App and server are separate processes; quit the app, sessions keep running; same Ghostty drawing engine so panes/scroll/select feel native 1:31–2:59
Remote without tmux/SSH ritual
  • Tailscale hosts: Install Rex on both machines, same Tailscale account, enable HTTPS certs, add remote host; host picker starts a session on the Mac mini—laptop can power off while remote work continues (local sessions still pause on sleep) 1:31–3:01
  • Agents too: `Rex skill setup` teaches AI the Rex CLI; caveats—Mac desktop app only, closed-source VC startup (business model before stable), tmux still better for SSH servers, Hurder already covers a lot OSS cross-platform 3:01–4:05
