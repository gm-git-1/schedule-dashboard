Don't Vibe Code Your Agent Infrastructure - Akshat Bubna, Modal

AI Engineer · Akshat Bubna, CTO of Modal · uploaded 8 Nov, 1:30 AM IST · 17:35
Verdict: skim from 6:21 — the sandbox basics are familiar, but the Ramp resource data and the scale numbers from 12:12 on are new.
🔁 Repeat: 'sandboxes for agents' — seen 22 times before, 'agent security' 34 times and 'secrets management' 14 times. New here: Real Ramp Inspect resource data, Modal's scale numbers (20M snapshots a week, 10,000 sandboxes a second for one customer) and the push for path-level network rules via proxy sidecars.
What an agent per spreadsheet cell needs
  • Every cell is an agent: Heavy AI's product runs a spreadsheet query where each cell is backed by its own agent, each in a Modal sandbox that can now hold several containers or microVMs, so the harness (the agent loop) is kept apart from where tool calls run, with a sidecar and shared storage per row; thousands must spin up and down per query 0:24–3:15
  • A workspace per agent: Ramp Inspect, Ramp's internal coding agent that now pushes almost every PR at Ramp, needs repo, dependencies and dev services together; Basis (accounting) needs documents and work papers; a game studio needs the engine and assets 4:03–5:00
  • Persist without paying for idle: A Basis agent may wait days for an accountant's reply, so state is kept by snapshotting the whole root filesystem, a single directory like `node_modules`, or a shared volume, and compute runs only while the agent works 5:00–6:21
  • Elastic resources: Ramp's sandboxes vary hugely in CPU and memory, between sandboxes and over time; provisioning for peak would mean about 15 cores and 15 GB of RAM per sandbox, so Modal grants resources on demand and bills only for that window 6:21–7:41
GPUs, collaboration and guardrails
  • GPUs on demand: Claude Science ships with a Modal integration to offload CPU preprocessing or GPU science models; agents hill-climbing a training run in GPU sandboxes can swap GPUs and run ablations in parallel 7:41–9:02
  • Shared files and "dreaming": Sub-agents and humans share filesystems, and background memory updates are just files, so the filesystem needs speed and consistency (repeat) 9:02–9:57
  • Network control beyond domains: Domain allowlists aren't enough; users want rules on specific paths of services like Datadog or GitHub, credentials injected so the agent never sees them, and their own lightweight proxy sidecar, as Ramp does 9:57–11:20
  • Observability the agent can read: Failed-training logs, GPU utilization and sandbox budget are exposed to the agent so it can debug and retry by itself 11:20–12:12
Why not build it yourself
  • Reliability, security, scale: Modal sees about 20 million snapshots a week, roughly 8 PB of snapshot data a day and 2.6 million new volumes a week; one personal-assistant customer needs 10,000 sandboxes a second, close to a million running, each living 2–3 minutes and interactive in under a second; CPUs are scarce too, so capacity is pooled from several hyperscalers and neoclouds 12:12–14:54
  • Pets, cattle, microbes: With the "brain" (harness) separated from the "hands" (sandbox), harnesses will create, snapshot and discard environments on the fly, more like an ocean of self-evolving microbes than identical cattle 14:54–17:10

Build Your Own Finance Agent Inside ChatGPT - Stefano Fabbri & Oliver Steffmann, OpenAI

New here: ChatGPT for Financial Services itself was covered in Joseph Kim's 23 Oct talk; new here are how plugins, plugin extensions and Codex enterprise policies fit together, plus practical cost and eval tips. Long stretches are hands-on setup with little content.
ChatGPT for Financial Services (repeat)
  • Three surfaces: ChatGPT, ChatGPT Work (for knowledge workers, runs agents and plugins) and Codex (for engineering work) 4:57–5:40
  • Built-in data: Same model, but the product bundles data from Daloopa, LSEG, PitchBook, Crunchbase and others (SEC filings, about 15-minute delayed market data, news, private company profiles, earnings transcripts), each pre-processed into an LLM-friendly format with custom tool calls rather than custom embeddings; enterprise-only and web-only, not reachable from the CLI (repeat) 5:40–10:06, 31:00–36:00
  • Finance plugins: A plugin is skills plus MCP connections, built with top banks and asset managers; the idea is that the plugin covers about 80% and you customize the last 20% (pitchbook prep, earnings analysis, valuation, LBO modeling) 10:06–13:00
Building on it with Codex
  • Skill, plugin, extension: A skill is reusable markdown; a plugin zips skills, MCP servers, tool config, auth and UI components; plugin extensions, announced at Dev Day, add your own icons, settings, navigation and context-triggered UI inside the Codex desktop app, with web support still to come 19:02–28:00, 55:00–59:00
  • Ship inside an approved surface: Rather than building a separate app with its own login and access control, deploy a plugin through ChatGPT Work's plugin creator or the enterprise Codex rollout, connected to internal data through your own MCP server 48:20–53:00
  • Cost tip: Token efficiency has been clients' top priority for three months; use Astra for new research or codebases, but with good skills the cheaper Luna or 6.1 Sol handle repeatable tasks, and a smart orchestrator with Terra or Luna sub-agents gets about 95% of the result 42:00–45:00

Q&A highlights
  • Deep research as a plugin: A planner, sub-agent and critic financial-research app first built on the API was rebuilt as a Codex plugin; the Codex harness (app runner) is open source and OpenAI's models are post-trained on it; compaction let 5.5 replicate a quant paper on Brownian-motion option pricing over about two hours 1:09:00–1:21:00
  • Sandboxing: Admins push a managed `config.toml` that limits which URLs, folders and plugins Codex can reach, plus a "guardian" that auto-approves non-critical actions 1:28:00–1:32:00
  • Evals and goal mode: The hard part of evals is subject-matter knowledge, so start simple before adding an LLM judge, ask the judge yes or no rather than 1–5, and try the new Luna-based Decision API that returns yes/no with a confidence; Codex goal mode hill-climbs a numeric target for autoresearch 1:38:00–1:45:00
  • Writing back: A proxy-voting plugin writes reports and sources back to an app server through an extension, keeping auditable logs of every decision 1:47:00–1:50:00

Your Financial Agent Needs to Show Its Work - Anirudh Veeraragavan, Fieldguide

AI Engineer · Anirudh Veeraragavan, Fieldguide · uploaded 7 Nov, 11:30 PM IST · 13:28
Verdict: worth watching — short, concrete and reusable for any regulated agent.
🔁 Repeat: 'AI for finance' — seen 31 times before, 'human-in-the-loop review' 35 times and 'evals for agents' 62 times. New here: A tight four-control framework (state-aware authorization, replayable step records, versioned and hashed citations, auditing the eval set itself) worked through one bank reconciliation.
Why "the model said so" fails
  • The opinion is the product: In audit what matters is the reasoning behind a decision; when an inspector asks why a test was sufficient, your evals and metrics don't answer it 0:00–2:18
  • Stakes: Peregrine Financial Group claimed over $200 million in its accounts for 20 years while the bank held only $5 million 2:18–3:05
  • The bar: An experienced auditor new to the work must be able to follow the agent; the example is a fictional freight-lines client with $2.9M at the bank, $2.7M on the books and 41 reconciling items 3:05–4:27
Four controls
  • Authorization: The agent correctly flipped a human-flagged check to "no exception" after new evidence, but it shouldn't have, because the reviewer's sign-off no longer matched what they saw; permission depends on the object, its state and the time, so agents draft only unreviewed rows 4:27–5:37
  • Execution records: Logs can't explain why a 2028 rerun disagrees with the 2027 run; a chain of steps with IDs, inputs and outputs, marked deterministic or LLM, lets you rerun one step and find exactly where the runs diverge 5:37–7:33
  • Evidence provenance: A citation like "January bank statement, page 2" is useless; a citation is an identity with a document ID, version and content hash, which lets you enforce rules like bank-sourced evidence only 7:33–8:44
  • Eval integrity: Gold data from past reviewed audits can be wrong; of 9 misses behind a 97% score, 4 were eval errors, while 12 "correct" cases were actually wrong after methodology changes 8:44–10:09
When to hand off
  • Stop and ask: Escalate when the agent would overwrite reviewed work, runs disagree, or evidence breaks the rules; make escalations easy to verify but not easy to approve, because of automation bias, and aim for the agent handling about 80% 10:09–12:16
  • Beyond audit: The same four questions apply to approving or declining credit and to closing or escalating anti-money-laundering alerts 12:16–13:10

How to Get Frontier Coding Results at 70% Lower Cost - Nouha Dziri, Cohere

AI Engineer · Nouha Dziri, Cohere · uploaded 7 Nov, 1:30 PM IST · 31:22
Verdict: worth watching — rare controlled numbers on multi-agent cost versus reward.
🔁 Repeat: 'multi-agent / A2A' — seen 20 times before, 'token costs / AI spend' 21 times and 'coding agents in production' 70 times. New here: Actual experimental numbers on where extra agents pay off (planning on ProgramBench, implementation on Commit0), lead-versus-worker model mixing and how little agents talk to each other.
Setting up the experiment
  • Teams as a new axis: Besides thinking longer or sampling more, a lead can split work among workers with fresh contexts that report back compact results; left alone, frontier agents mostly built their own versions and stepped on each other 0:00–4:00
  • Minimal harness: A hierarchical lead with a `delegate_agent` tool and a shared bash workspace, tested with a blocking lead (waits for workers) or an async lead, on ProgramBench, where agents must reimplement a program they can run but not read; on FFmpeg the best model passes only 10% of tests 5:00–7:40
  • Teams win, at a price: A team beats a solo agent by almost 10 points but costs 4–7 times as much; the async lead builds on guesses and sometimes submits while workers are still running 7:40–9:00
  • Heavy prompting helps: A detailed plan-implement-verify prompt lifts even the solo agent by about 6 points and lets the async lead catch up, but costs stay 6–7 times higher 9:00–11:00
Where the next dollar goes
  • Put workers at the bottleneck: Planning-only workers on ProgramBench match the heavy-prompt team at half the cost, with each planning dollar buying about 1.6 times more reward; implementation or verification workers add cost only, and the heavy-prompt lead made 830 more delegation calls (around $500) for nothing; on Commit0 the bottleneck is implementation instead 11:00–20:00
  • Strong lead, cheap workers: With GPT-5.6 Luna, Terra and Sol, a Sol lead with Luna workers nearly matches all-Sol at 60% lower cost, but cheap workers can't rescue a weak lead: Terra with Luna workers scored 51% against Sol alone at 57% ("the lead sets the ceiling, the workers set the price") 20:00–22:00
  • Scale planners: Going from 2 to 16 Luna planners, the 16-planner team is 38% cheaper than an all-Sol planning team and 70% cheaper than workers at every stage 22:00–24:00
How agents actually talk
  • Hierarchy by default: 84% of messages go worker to lead, with less than one worker-to-worker message per task; about half of Luna's messages were malformed, and messaging added nothing for Sol and Terra while costing Luna teams 4–7 points 24:00–27:00
  • Not every model leads: GPT-5.6 delegates often and gains up to 7 points and Claude gains about 6, while Opus 4.7 rarely delegates and Gemini delegates a lot but gains nothing 27:00–28:00
  • Open questions: Organizing thousands of agents, letting agents design their own team, and multi-agent safety for swarms running 24/7 28:00–31:22

AI Can't Make Up a Number It Can't Look Up - Vinoo Ganesh, Kepler

AI Engineer · Vinoo Ganesh, Kepler (ex-Citadel) · uploaded 7 Nov, 1:30 PM IST · 18:28
Verdict: skim from 4:17 — if you saw his 25 Oct talk, only the retrieval funnel and tenant-security list (9:07–12:25) are new.
🔁 Repeat: 'AI for finance' — seen 31 times before. New here: Same speaker and core architecture as his 25 Oct talk "Do Not Let Models Invent Numbers"; the new parts are the three-way breakdown of wrong numbers, the retrieval funnel numbers and five tenant-security failure modes.
Why Wall Street still doesn't trust AI
  • Verification gold rush: About $270 million of VC money went into verification layers in three months, and a VC handed Kepler's deck to a competitor, which copied the verification step but not the structure behind it 0:00–2:00
  • Hallucination is alpha: Firms make money on creativity, so the fix is structural, not waiting for models to stop making things up; trust means someone to blame, and while 80% of finance execs trust their numbers, 31% find errors 2:00–4:17
  • Three sources of wrong numbers: The wrong document, the wrong number from the right document (Palantir's 2023 revenue read off its 2025 10-K) and models doing math by predicting tokens 4:17–5:50
How Kepler is built (repeat)
  • Code writes every number: Pre-processing turns every fact into an ID; the model plans and points to IDs, and if it can't dereference a pointer it can't print the number (repeat) 5:50–9:07
  • Search wide, then narrow: ANN plus BM25 pulls up to 200 documents, reciprocal rank fusion cuts to about 60, then cross-encoders rerank; LLMs tend to search depth-first because going wide is expensive 9:07–10:46
  • Tenant security: Five ways it goes wrong: forgetting the tenant filter (Citadel seeing Millennium's documents), a caller impersonating another firm, stale results, direct reads skipping search rules and hitting an unpopulated index; the fix is scoping every search with security built in 10:46–12:25
  • Verified, corrected or refused: Refusals dropped sharply in production but not to zero, so a post-processing check stays; today most finance AI tools mostly format PowerPoint decks 14:00–16:31
  • Ask your vendor: Does the model write pointers, is every citation and every arithmetic step source-checked, and what happens to a number that came from nowhere 16:31–18:28

How Agents Cut Hour-Long Data Checks to 5 Minutes - Amol Kapoor & Clifford Ressel, Nori Agentic

AI Engineer · Amol Kapoor & Clifford Ressel, Nori Agentic · uploaded 7 Nov, 12:30 PM IST · 19:34
Verdict: skim from 10:50 — the first ten minutes are a finance primer, and the agent pattern itself is familiar.
🔁 Repeat: 'AI for finance' — seen 31 times before and 'human-in-the-loop review' 35 times. New here: The security-master problem (how asset managers map instruments) and a concrete before/after at a Fortune 200 asset manager.
Why private assets break the data
  • Finance got weird: Secondaries volume hit $240 billion in 2025, up 50%, with forecasts of $32 trillion in alternative assets by 2030; private-asset terms live in PDFs, Box folders, Outlook and Zoom transcripts 0:21–3:24
  • What a security master is: The firm's master database of every instrument it holds, feeding risk, P&L and compliance, joined across vendors through identifiers like Bloomberg FIGIs, LSEG RICs, ISINs and CUSIPs 4:19–7:03
  • Even Google is messy: GOOG versus GOOGL share classes, entity-level data that won't join on ISIN and the same share on several exchanges; private deals have no shared identifiers at all, so data grows one-to-one with assets 7:03–10:50
The agent in production
  • Before: A Fortune 200 asset manager diffs about 50,000 assets by about 200 columns every day, and each changed cell took about an hour of manual checking 10:50–12:34
  • After: For each change a cloud agent spins up, running a locally deployed open-source model so data stays on-prem, checks Box PDFs, Bloomberg and a slice of email, writes an explanation with citations, recommends keep or discard and pings the cell's owner in Slack; the human part drops to about 5 minutes 12:34–14:37
  • Expertise in plain English: A generic agent (Claude Code, OpenCode, Pi) customized with skills and agent markdown files rather than custom infrastructure (repeat) 14:37–15:35
  • Agents come to you: The same cloud-agent infrastructure should run SecMaster, audit and code-review agents, with only instructions, tools and triggers differing 15:35–17:19
Lessons
  • Three takeaways: Adoption is a collaboration problem between domain experts and engineers; aim for 95% automation and keep a human in the loop; and agents make "accidental complexity" (Fred Brooks's term) cheap to handle 17:19–19:00

Did Claude Just Fix AI Overfitting? (OPAL)

Better Stack · Andress (Better Stack) · uploaded 8 Nov, 4:49 AM IST · 8:48
Verdict: worth watching — a clear, honest replication of an agent-in-the-training-loop idea.
The experiment
  • Sabotaged data: Two copies of a ResNet-18 trained on CIFAR-10 at the same time, with 4,500 of 45,000 training labels deliberately wrong; the agent sees scores on 5,000 clean images, and 10,000 test images are held back; run on one rented H100 on RunPod with Claude Opus 5.5 as the agent 0:00–3:44
  • What OPAL is: A PyTorch library from the "Reactive Optimizers" paper that wraps your optimizer, pauses training now and then, hands an agent a report and lets it rewrite the optimizer's code but not the model, data or eval; the paper improved an image model's FID from about 36 to 24, with small gains on already-tuned recipes 0:56–2:42
What Claude did
  • Early tries: It replaced the optimizer with its own update rule at once, spotted overfitting around epoch 24, then failed with flooding, weight noise and last-layer flooding (accuracy fell to about 52%), noting "Never use flooding again" 3:44–5:00
  • The pivot: It let the model take big noisy steps while keeping a running weight average, which lifted clean accuracy to 78%; when it found the model still about 89% memorized it wrote "my mechanism was wrong", and bigger steps then cut memorization from about 87% to 4% 5:00–5:53
  • Results: 79.1% versus 74.4% test accuracy, loss 0.70 versus 2.39, and only 250 of the 4,500 wrong labels memorized versus all of them for the fixed recipe; the paper's released run got 80% 5:53–7:02
Caveats
  • Not new math: What Claude landed on is close to stochastic weight averaging from 2018, and plain fixed averaging alone got about 77.5%; it was one small run, the agent run took over three times longer waiting on Claude, and the captions put its token cost at about $760 7:02–8:48

Anthropic Replaced Git. OpenAI Did the Opposite.

Better Stack · Josh (Better Stack) · uploaded 7 Nov, 5:45 PM IST · 9:18
Verdict: skim from 2:46 — skip the worktree basics; the Pando and Scion comparison is the new part.
🔁 Repeat: 'coding agents in production' — seen 70 times before and 'merge queues / CI' 6 times. New here: OpenAI's Pando and Anthropic's Scion source-control numbers; the Git worktree demo repeats Better Stack's 31 Oct Worktrunk video.
The problem
  • Agents overload Git: Anthropic went from about 2,500 to over 30,000 merged code changes a day in 4 months, and OpenAI's monorepo reliability sometimes fell below 90% 0:00–0:46
  • Worktrees for now: Two commands give each agent its own folder and branch so they stop editing the same files; it doesn't remove later merge conflicts (repeat) 0:46–2:46
Two fixes
  • OpenAI Pando: A new Git backend that handles updates to different branches immediately and caches pack files for CI, at the cost of cross-branch reads not being perfectly in sync; median push latency fell by nearly 80%, it serves most of a petabyte a day, and one engineer designed the core, mostly implemented by Codex, in about 10 weeks 2:46–3:55
  • Anthropic Scion: A full Git replacement for a main branch history near 100 GB and about 25 million CI checkouts a day, mostly agents; clients fetch only the files they need and commits, merges and history run on the server; about 200 times less CPU and memory than the old Git mirroring, checkouts from minutes to seconds and about 25% of CI CPU recovered, but code review, search and CI had to be rebuilt 3:55–5:00
What to do yourself
  • Caveats: Neither is usable today, and the numbers are self-reported on workloads most teams never see; OpenAI is upstreaming some Git client improvements 5:00–6:38
  • Four practical steps: Use worktrees per agent, sparse checkouts in big repos, and CI caching, duplicate-job removal and running only relevant tests; review and validation become the next bottleneck 6:38–9:00
