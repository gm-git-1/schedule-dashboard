AI Writes the Code. So What's Left for Engineers? - Laurie Voss, Arize AI

AI Engineer · Laurie Voss, head of developer relations, Arize AI (npm co-founder) · uploaded 25 Oct, 4:30 AM IST · 27:09
Verdict: skim from 11:21 — the first 11 minutes recap his code-review data; the product-engineer and junior-hiring argument after that is the new, well-sourced part.
🔁 Repeat: 'AI-generated code validation' — seen 22 times before (incl. his own "Death of the Code Review" talk). New here: code review is treated as only the first bottleneck; the talk is really about what comes after it and which job is left for humans.
The bottleneck keeps moving
  • 8x the code, 30% faster shipping: Developers using autonomous coding agents write 741% more code but ship only 30% faster, because humans can't review faster; a Cisco study found review accuracy drops off past about 450 lines per hour, so a 10,000-line diff would take a week (repeat) (3:03–4:11)
  • Machine reviewers aren't there yet: Copilot does more than one in five GitHub code reviews, but four AI reviewers tested on the same code found real bugs and none of the same ones. Dex Horthy walked back six months of "don't read the code", and Amazon now requires senior engineers to sign off after agent-caused outages (repeat) (4:38–6:53)
  • "Would you merge it?": Cognition's benchmark asks whether a maintainer would merge the PR instead of whether tests pass, and the pass rate falls from 87% to 54%. The gap is style, side effects and history that live in the maintainer's head, i.e. the sense of what "good" means (6:54–8:00)
  • Theory of constraints: Using Goldratt's The Goal, he argues that fixing review moves the bottleneck to operations and then security. He expects those to take 5–10 years to automate, not 12 months, and assumes demand for software is effectively infinite (8:02–11:19)
What agents won't eat
  • Finding out what people want: "Keep track of my orders" means something different for a bakery, an auto parts store or a factory, and that knowledge isn't in the weights; you have to talk to the person. Citing Fred Brooks's essential vs accidental complexity, he bets describing the problem and defining "good" is where the bottleneck stays for 10 years (11:21–14:54)
  • Writing it down moves it again: Anything cheap to verify can be trained against. Cursor's BugBot turns every thumbs-down into a rule (about 44,000 rules now), which is why he thinks ops and security will fall once written down (15:08–16:02)
  • The product engineer: Like the 1960s systems analyst, the engineer and PM roles are merging into one job that finds what people need, defines good and ships it with agents typing. Forward-deployed engineer postings rose 800% in 9 months of 2025, with average pay of $240,000 (16:05–18:36)
Juniors, craft, and what to do
  • The junior ladder is gone: Well-specified tickets now go to agents. Labor data since January 2023 shows employment of engineers aged 22–25 collapsing while 41–49 rises. Google's APM-style programs turn out about 50 a year (about 1,000 across all copycats) versus the 10,000+ needed; IBM is redesigning entry-level roles around talking to customers and writing specs (19:45–22:54)
  • For people who love the craft: Maybe what you loved was the moment before typing, when you figured out the problem. Programming survives the way woodworking survived the furniture factory, but it won't be what you're paid for. He predicts an ugly 10 years, then a bigger profession shaped like product engineering (22:57–25:05)
  • What to do now: Review only high-blast-radius code, delegate whatever is cheap to verify, put your best people's judgment into specs, rubrics and evals, and measure shipped output, how often review comments get acted on, and the gap between "tests pass" and "would merge" (25:15–26:28)

Your Agent Fix Just Broke Something Else - Sofia Jakovcevic, Arize AI

AI Engineer · Sofia Jakovcevic, forward deployed engineer, Arize AI · uploaded 25 Oct, 12:30 AM IST · 19:25
Verdict: skip — the +17/−17 example is a good hook, but the rest repeats Arize's earlier eval, skills and self-learning-loop sessions.
🔁 Repeat: 'evals for agents' — seen 36 times before. New here: framing evals as regression testing, with the example that one prompt line gained 17 points on one metric and lost 17 on another.
🔁 Repeat: 'agent observability' — seen 19 times before. New here: not much beyond "the diff tells you what changed, the trace tells you what actually happened".
🔁 Repeat: 'self-improving agents' — seen 13 times before (incl. two earlier Arize sessions on skills and self-learning loops). New here: nothing substantial; the closing section restates coding agents reading traces and fixing themselves.
🔁 Repeat: 'LLM-as-a-judge' — seen 7 times before. New here: nothing; a standard explanation of binary task-completion judges.
Why agent fixes regress
  • +17 and −17: A security engineer adds one line asking a support agent to confirm before any action. A week of production evals shows action safety up 17 points and task completion down 17, because users leave before confirming; the net is zero, so improving one dimension didn't improve the agent (2:26–4:43)
  • Agents fail at runtime, not in code: The reviewer saw a one-line markdown diff, but the change altered steps, sub-agent hand-offs and tool calls across possibly thousands of trajectories that only show up in traces, so "traces are becoming the new source of truth" (4:48–6:24)
The five-step regression loop
  • Datasets from production traces: Pull real queries and tool calls instead of synthetic data, covering typical workflows, known failures, edge cases and the successful workflows you want to protect (often forgotten) (6:48–7:49)
  • Evaluators (repeat): LLM-as-a-judge turns subjective metrics like hallucination, tool trajectory or step efficiency into 0/1 or 0–5 scores; use code-based evals for deterministic checks (7:50–9:49)
  • Baseline, compare, gate in CI: Run the agent plus evals on the dataset for a baseline (`run_experiment` in the SDK), rerun after each prompt, tool, hand-off or model change (e.g. proving a 5x pricier model pays off), and block PR merges in GitHub Actions until regression criteria pass (9:51–11:45)
  • Demo: In Arize, the refund agent's experiments compare variants until one gets +18 on action safety and +6 on task completion. The prompt playground tests two prompt versions side by side on a 100-row dataset with task-completion and action-safety evals; the agent playground calls a remote multi-agent system over HTTP (11:48–15:29)
Closing the loop (repeat)
  • Every failure becomes a test, and agents fix themselves: Failed production traces feed back into the regression suite. Arize's public skills repo lets coding agents read traces and propose fixes, so they aren't "pushing PRs blind" from static code (repeat) (15:32–19:14)

How Bridgewater Turned 100 Million Documents Into an Edge - Sam Green & Aaron Linsky, Bridgewater

AI Engineer · Sam Green (team lead, Applied AI) & Aaron Linsky (head of product engineering), Bridgewater Associates · uploaded 24 Oct, 8:30 PM IST · 16:45
Verdict: worth watching — concrete numbers (100M docs, P@10 60%→90%+, 52 vs 15 sources) and practical search and adoption lessons for anyone building retrieval for both people and agents.
🔁 Repeat: 'RAG vs long context' — seen 11 times before. New here: a hand-built 200-question benchmark that took precision@10 from ~60% to 90–95%, and why they moved to Turbopuffer's "native filtering" (between pre- and post-filtering) for agent-scale filtered vector search.
🔁 Repeat: 'AI for finance' — seen 6 times before. New here: a hedge fund's own permissioned corpus of 100M+ documents tagged to its internal ontology, shown beating open-web search on the same investment question.
🔁 Repeat: 'always-on agents' — seen 5 times before. New here: an "investor workbench" where an always-on agent proposes topics as evidence cards and writes the investor's findings back into the corpus.
What the Vault is
  • Three lessons up front: Humans and agents need different things from a data platform, the biggest impact comes when one tool serves both, and the real prize is agents as proactive participants rather than reactive tools (0:37–1:09)
  • Same rigor as structured data: After decades of time-series models on carefully built structured data, LLMs opened up news, research, transcripts, policy documents and internal memos and meetings, which needed the same cleaning and governance; no vendor gave enough control, so they built it (2:14–3:23)
  • Scale and tagging: 100M+ documents from 135 external sources plus everything inside Bridgewater, thousands added daily, each tagged with countries, concepts, markets and, most importantly, the time period discussed (3:41–4:11)
  • Open web vs Vault: Asked "How is AI infrastructure investment impacting the Korean won?", an enterprise chat client found 15 sources, used one or two, leaned on a July note and admitted it couldn't establish consensus; with the Vault it scoped to Oct 1–8, found 52 candidates and drew on seven (4:23–5:51), (5:54–6:45)
Search for humans vs agents
  • Different readers: Humans read ~300 words a minute and need precision; agents read ~30,000, are far less sensitive to precision, and hit 100+ queries a second (swarms thousands) versus ~100 queries an hour from 300 human users (7:20–7:52), (10:56–11:25)
  • "Vault search is bad" — benchmark it: They hand-labelled ~200 questions with the best documents (including look-alike decoys) in under a week; precision@10 was ~60%, and five improvements ending with agentic search took it to 90–95% (8:29–9:27)
  • Filtering at scale: Production traces nearly always had a date, source or asset condition; post-filtering is fast but loses recall, pre-filtering has recall but is slow, so they switched to Turbopuffer, whose native filtering searches only nearest clusters containing matches (9:35–10:49)
Adoption and what it enables
  • Move habits, don't replace them: Investors lived in broker email with subscriptions and folder rules, so subscriptions became saved searches and folders saved collections; then came Q&A over all data, topic feeds and handing collections to agents, plus chat, phone app, Slack, IDE and a CLI "because agents love CLIs" (11:38–13:00)
  • Built on top: A "pocket analyst" doing hours of research in minutes for a few dollars, a multi-day "researcher", custom models feeding a macro "forecaster", and investment signals turning unstructured data into tradable strategies (13:14–13:57)
  • Investor workbench: An always-on agent presents topic cards with a summary and the exact evidence; when investors dig in with the agent, the results are captured back into the Vault so the corpus compounds (14:27–16:01)

Can AI Understand a Distressed Credit? - Harneet Kaur, Axim Intelligence

AI Engineer · Harneet Kaur, founder & CEO, Axim Intelligence · uploaded 24 Oct, 2:30 PM IST · 14:15
Verdict: skim — one interesting case study with clear numbers (62%/25% → ~25%), but short, with no ground truth and a mid-talk laptop outage (9:10–10:19).
🔁 Repeat: 'AI for finance' — seen 6 times before. New here: distressed-credit prediction with no ground truth, where two frontier models disagreed on bankruptcy odds until a layered reasoning process made them converge.
Why distressed credit is hard
  • What distress means: A credit is a company's bond or loan; distress comes from cyclical, operational (e.g. a food recall) or secular (e.g. AI disrupting software) risk, and outcomes include bankruptcy, a liability management exercise, or an out-of-court negotiated exchange (0:55–2:28)
  • Old tools fall short: The question used to be binary (default or not); scores like the Altman Z-score are static for situations that change monthly, private credit has made pricing opaque, and the alternative is manual analyst work that doesn't scale (2:37–4:00)
  • Understanding = predicting: Rather than benchmarking factual questions (like which debt is senior, as legal/finance AI firms do), she defines understanding as producing a probability distribution over what happens next (4:39–6:07)
The iHeartMedia experiment
  • Two models disagree: On iHeartMedia (bankrupt in 2018, another stressed transaction in 2024, still live with no ground truth), "Astra 6" on max intelligence and Opus 5.5 gave sharply different odds, favouring negotiated restructuring vs bankruptcy respectively; she leans toward Astra (6:20–7:55)
  • Benchmark each layer: Split the work into extraction (e.g. EBITDA; mostly solved for public companies, still hard for private-loan Excel/PDFs), derivation (leverage from EBITDA and debt), judgment (is it distressed?) and only then prediction (8:24–9:03), (10:22–11:05)
  • They converge: With the structured process, both went from 62% (Opus) and 25% (Astra) bankruptcy to ~25% bankruptcy, agreeing negotiated restructuring is most likely (11:23–12:02)
Takeaways
  • Convergence isn't correctness: On non-verifiable questions with the same structured context, models show no predictive edge over humans; agreement could be wrong, and backtesting on history adds look-ahead bias, but a process that converges on shared probabilities is effectively what a market price is (12:08–13:36)

Proving Alpha: How a Hedge Fund Measures AI's ROI - Hari Kumar, Contour Asset Management

AI Engineer · Hari Kumar, head of AI, Contour Asset Management · uploaded 24 Oct, 1:30 PM IST · 18:24
Verdict: skim from 2:25 — the A/B-test setup and cost-per-useful-insight metric are useful, but he deliberately keeps it vague and gives no results or numbers.
🔁 Repeat: 'AI ROI measurement' — seen 7 times before. New here: live A/B tests of an analyst's research on one name across an earnings cycle with and without AI tools, and a "cost per useful insight" metric.
🔁 Repeat: 'AI for finance' — seen 6 times before. New here: a ~15–20 person, $6B TMT long/short fund using agents to resurface dropped ideas when timing turns favourable.
Measuring research ROI
  • The mandate: Contour (fundamental long/short, ~$6B AUM, mostly TMT) hired him a year ago to show AI impact across the firm, starting with research; P&L proof is still "to come", so he keeps it to process (0:26–2:21)
  • Live A/B tests: With ~10 analysts each covering 30–40 names, they record an analyst's full workflow on one name across a three-month earnings cycle without AI, then again with tools added one at a time, e.g. agent-run expert calls with self-written vs agent-synthesized notes (2:26–4:59)
  • Process over P&L: Theses can take 6–12 months to hit the stock price, so ROI is judged on whether surveys and model updates actually change how people work rather than just adding volume (5:43–6:14)
  • Cost per useful insight: They track insights per analyst per day, time spent per name and eventual P&L, combining them into a "cost per useful insight" tied to the tools used (10:29–11:40)
Agents in the workflow
  • Idea and timing agents: Agents add layers to each analyst's ideas, and track notes on ideas dropped after a day so they can flag them to the analyst, PM and trader when the market makes them interesting again, since timing matters most (6:52–7:33), (7:35–8:54)
  • Combining alt data: Datasets like Yipit's credit card panels used to sit in isolation; via MCP/API access they now feed agents alongside expert call transcripts (9:06–9:59)
  • Trading, ops, compliance: Agents track entry/exit timing and positions so traders can feed ideas to analysts; ops and compliance workflows scattered across Bloomberg and order systems (order reconciliation, vendor info) are being consolidated into one internal tool (12:15–14:32)
Spend and hidden costs
  • Up-level existing subscriptions: Instead of using AlphaSense or Yipit in their portals, or buying a Rogo or Kensho-style platform, they pull those feeds into an internal platform that learns each analyst's habits and model patterns (14:52–16:37)
  • Fixing tools counts too: Model calls and connectors break every few days, and the time spent fixing them is part of the ROI equation; he says it's shrinking (16:46–17:45)

The AI Bug Apocalypse Has Officially Started

Better Stack · Andras · uploaded 25 Oct, 3:00 AM IST · 9:05
Verdict: worth watching — a tight 9-minute roundup with concrete numbers and a patch list; only the PHP2Shell part repeats.
The Linux kernel leak
  • Sent to the wrong list: On October 22, Trend Micro's Zero Day Initiative sent unpatched Linux kernel vulnerability reports to the public kernel mailing list instead of the private security list (reported by Phoronix). Greg Kroah-Hartman replied to each one asking why; it looks like a mistake (0:00–1:28)
  • Two 9.0 SMB bugs: A remote code execution bug in SMB Direct caused by an integer underflow, and a race condition in KSMBD, the kernel's built-in SMB server. SMB servers accept network input from machines that never logged in, which is how WannaCry spread in 2017. The rest are local privilege escalations in networking and the VMware graphics driver, plus an NVMe target info leak (1:28–3:00)
  • AI-found bugs are public by default: Willy Tarreau said in March that security reports went from 2–3 a week to 5–10 a day; in May Linus Torvalds called it almost unmanageable as people run the same AI tools on the same code. One leaked bug had been reported by someone else a week earlier, and kernel docs now say AI-found bugs should be reported publicly (3:10–4:06)
Black October
  • The rest of the month: PHP2Shell (repeat, covered in an earlier Better Stack video), the eMudhra certificate mess, a CVSS 10 GitLab bug dating to 2014, a Node.js RCE fix, and an Axios report on unauthorized AI agents inside US bank accounts. Much of it is a disclosure wave rather than an attack wave; OpenAI says AI found the PHP bugs before attackers did (4:07–5:03)
  • The numbers: The UK NCSC warned in May of a "vulnerability patch wave". The Mythos model reportedly found 90 critical and 141 important SharePoint bugs in April, faster than Microsoft could fix them; July's Patch Tuesday fixed 600+ bugs; Chrome 149 and 150 fixed 1,072 security bugs, more than the previous 23 releases combined, including a 13-year-old sandbox escape. Google is testing twice-weekly security updates (5:10–6:21)
What changes and what to do
  • Fixing is the new bottleneck: Finding bugs is now cheap, so triage, fixing and shipping are the slow part, and attackers diff each patch, so the window to exploit keeps shrinking. Banks can't tell whether an agent in a customer's account is acting for them, so most are moving to read-only agent access (6:23–7:24)
  • Patch continuously: Chrome's team told Wired that findings drop off once the AI-findable bugs in a mature product are fixed. Advice: follow the NCSC's update-by-default policy starting with internet-facing systems, automate updates, replace what can't be patched; this week update PHP, watch for the SMB fixes, unload KSMBD if unused, and update GitLab and Node.js (7:27–8:20)

They Shrunk Qwen 27B to 7.9GB... Here's What It Lost

Better Stack · Josh · uploaded 24 Oct, 2:00 PM IST · 8:51
Verdict: skim from 2:50 — a useful reality check on a viral local model; the benchmark sources and the 6:18 trade-offs matter more than the demo.
🔁 Repeat: 'open source / local models' — seen 43 times before. New here: a 2-bit quant tuned to keep tool calling rather than overall quality.
🔁 Repeat: 'LLM releases / benchmarks' — seen 39 times before. New here: it beats the full model at tool calling but loses a lot on math, and the benchmarks come from its own maker.
🔁 Repeat: 'inference / serving' — seen 32 times before. New here: a smaller file didn't mean a faster agent, because prefill made it the slowest of three models in a real agent loop.
What Saluki is
  • 55 GB down to 7.9 GB: Underdog Saluki 27B is a compressed Qwen 3.8 27B. The original is a 55 GB download that needs a 64 GB Mac or an 80 GB machine, and even Unsloth's 4-bit is 16.5 GB. Saluki was downloaded almost 400,000 times in 10 days (0:00–0:59)
  • Local tool-calling demo: On a llama.cpp server with GPU offload, flash attention and 32K context, a weather tool for several cities produced two correctly formatted calls, and a question that needed no tool got a direct answer (1:11–1:53)
  • Tuned for one skill: Weights go from 16 bits to about 2.35 bits each. The model card says it was tuned specifically to keep tool calling, not math or reasoning (1:55–2:47)
Where the score comes from
  • Built on an ISTA quant: It starts from an existing 8.42 GB 2-bit quant by the ISTA lab, whose method picks the best quantization type for each tensor within a size budget. On Underdog's tool-calling benchmark, ISTA scored 76/120, Saluki 88 and the full model 84 (2:50–3:36)
  • No training details: Underdog hasn't said what it changed. The model card calls this a preview checkpoint, and no full-precision checkpoint has been released, even though someone porting it to MLX asked for one (3:39–4:12)
  • Vs. other small quants: Unsloth's IQ2_XXS (7.27 GB) and IQ2_S (8.37 GB) haven't been tested on the same benchmark. Ternary Bonsai 2 is about 6 GB but scored 70 and needs PrismML's llama.cpp fork, while Saluki runs on stock llama.cpp and Ollama (4:14–4:53)
  • Community results: One user ran it on a 12 GB RTX 3060 with 170K context at about 22 tokens/s. A community version with a multi-token prediction head went from 41 to 66 tokens/s on an RTX 3080. On a DGX Spark it scored 86 on single-turn BFCL, against 72 for the smaller Qwen 3.8 Flash Next at 4-bit, and 200 of 200 tool calls came back clean (4:56–6:00)
The catches
  • Math and coding drop: Eight of the nine benchmarks on the model card are tool-calling or BFCL-based. AIME 2025 math falls from 96.7 to 79, a 50-task SWE-bench Verified run from 33 to 30, and parallel tool calls score 42 with a strict parser and 55 with a lenient one (6:18–6:52)
  • Not faster in practice: In a real agent loop on the DGX Spark it was the slowest of three models, at about 10 steps a minute, because prefill was the bottleneck (6:59–7:23)
  • Who should use it: All the model-card numbers come from Underdog, and the full-model scores came from a different test harness. Use Saluki for local tool-calling agents on 12–16 GB, with thinking off and temperature 0. With 24 GB free, if you care about coding, math or reasoning, use the normal Q4 (7:26–8:26)

Why Rust Is The New GOAT For AI

Better Stack · speaker not named · uploaded 24 Oct, 11:30 AM IST · 6:24
Verdict: skim from 2:57 — the opening history is familiar, but the Copilot rewrite and agent-port numbers are worth seeing.
🔁 Repeat: 'coding agents in production' — seen 47 times before. New here: GitHub's Copilot agents ported its runtime from TypeScript to Rust in about 14.5 weeks.
The shift to Rust
  • Who has moved: Elon Musk answered a 2023 "AGI will be built in Python" tweet with "Rust", and now says xAI's code is mostly Rust. GitHub rewrote Copilot's runtime in Rust, Bun (which Claude Code runs on) moved from Zig to Rust this summer, and OpenAI's Codex is now 97% Rust (0:00–0:30)
  • Origin and popularity: Mozilla's Graydon started Rust in 2006 after his building's elevator software crashed again. 1.0 shipped in May 2015, and in 2025, 72% of Rust users said they want to keep using it (0:45–1:22)
Why memory matters
  • Memory bugs dominate: In 2019 Microsoft said about 70% of the security bugs it assigned a CVE were memory-safety bugs, and Chrome found about the same share among its high-severity bugs. Android's share went from 76% in 2019 to under 20% last year as new code moved to Rust, and Google measured about 1,000× fewer memory bugs per line in its Rust code (1:24–2:08)
  • No GC pauses: A Discord Go service had garbage-collector latency and CPU spikes about every two minutes, and the Rust rewrite had none. In Rust each value has one owner and is freed as soon as the owner is done, and the compiler enforces this before the code runs (2:11–2:52)
AI tooling examples
  • Copilot from 5.25 s to 292 ms: The old TypeScript runtime meant every app using GitHub's SDK started its own Node process, using at least about 100 MB. The Rust version is one native file that apps load in-process like a plugin. OpenAI also dropped Node from the Codex CLI, partly because requiring Node 22+ blocked some users (2:56–3:47)
  • Developer experience: Compiler errors point to the exact line and suggest fixes, and Cargo was the most admired tool in its category in the 2025 survey. At Google, Android Rust changes are rolled back about 4× less often than C++ changes and spend about 25% less time in code review (3:49–4:21)
  • Agents did the port: Clear compiler errors let agents fix and retry. Copilot's own agents wrote most of GitHub's port, turning about 430K lines of TypeScript into 832K lines of Rust plus about 470K lines of tests in about 14.5 weeks. Only about 1.7% of their compiler errors came from Rust's memory rules (4:24–4:56)
  • Python on top of Rust: Hugging Face tokenizers ships a compiled Rust file, and tiktoken, Pydantic v2 and uv are all Rust underneath. Nvidia announced a way to write GPU kernels in Rust last month, but says it isn't production-ready. The takeaway: Python users don't need to switch, but CLIs and agent harnesses are moving to Rust (4:59–6:05)
